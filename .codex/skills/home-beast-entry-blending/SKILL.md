# 修圖技能檔案

## 啟動與範圍
使用者說「修圖技能檔案」即啟用本流程，不需額外口令。沿用當前對話已指定的卡片、部位、限制及批准，直接核對並處理已授權問題，不反覆問是否開始。若使用者只是詢問本技能的內容、列清單或審查規範，則只回答或審查，不據此修改卡圖。
目標不明時先查可用畫面與專案引用，仍無法辨識才問一個必要問題。說「測試」可依指定卡執行實際審查；已有局部修圖授權時直接修可證實缺陷，未見缺陷不為展示技能刻意改圖。
只修改本輪指定入口；先列必要檔案、檢查 Git 差異並保留其他工作。功能、公式、API、遊戲數值、其他卡片與未授權文案不動。修圖指令不是整張重繪或全站修改授權。

## 選對作業模式
| 模式 | 適用情境 | 修改界線 |
| --- | --- | --- |
| 首頁合成／構圖 | 遮罩、接縫、尺寸、接地、圖層、背景對比問題 | 保留原卡像素；調整該入口圖層、遮罩、背景及樣式 |
| 原圖局部修復 | 已確認原圖指定部位有缺損，且使用者批准修原圖 | 只修指定區域；保護臉型、姿勢、原色與相鄰細節 |
| 整張重繪 | 使用者明確要求整張重繪或改造 | 先鎖定可改區與不可改區，再讀局部修復與重繪參考 |
一般「細修、優化、啟動技能」不得自動升級成整張重繪。背景生成亦不授權重畫神獸。

## 先核實素材
從[六十張神獸索引](references/beast-card-index.md)查名稱、幼子／成獸／四大神獸與原卡路徑；再核對當前 renderer 覆寫、版本及瀏覽器實際來源，索引不是即時真相。
既有來源鏈：app/star-beasts/page.tsx → CatalogBeastCard → BeastCardFace／BeastCardTile 的 ART_V2。不要僅憑 high 欄位猜正在使用的圖。
已明確指定的角色與形態不自行替換；使用現有正式素材。原圖與修圖候選分開保存。

## 交叉細修流程
1. 取得原圖、當前首頁及修改前畫面。以「畫面方位＋解剖部位」定位，分清前掌、後腳及尾巴。
2. 記錄具體現象；分辨原稿缺損、遮罩切除、底景殘片、色差、縮放損失、層級遮擋。未證實原因標假設。
3. 只修已定位問題，優先恢復原圖已有像素；不猜畫鬍鬚、不改臉或全身比例。
4. 以相同尺寸、位置與狀態比較原圖／修改前／修改後／實際背景，檢查缺陷改善及周邊退步。
5. 尚有問題則針對該處重試；同一方法連續無改善即換方法。工具做不到時保留原稿、回報限制，不以無限重試或口頭承諾冒充工作。
6. 實際首頁引用、視覺與必要互動核對完成後才判定本張結果，再按已授權順序處理下一張。臨時 DOM 候選不算正式接入。

詳細技術與記錄方式見[精準合成參考](references/precision-compositing.md)。修改原圖時另讀[局部修復與重繪](references/local-repair-and-redraw.md)。

## 不降低的視覺基準
- 保留整套六十張的畫風、色調、角色辨識度及原有姿態；只改指定卡，不讓其他五十九張配合重做。
- 八字與白虎已接受版本是質感參考，不是所有物種的頭身比例或座標模板。每隻依自身原圖核對。
- 等比呈現、完整入框，不撐長外卡或改鄰卡湊尺寸；先量本卡與相鄰卡。
- 毛髮、鬍鬚、羽束、角耳、爪尖及尾尖逐段保持原有清晰度。硬質輪廓保留清楚邊界，細毛依原細線處理；禁止全部羽化、粗鋸齒、霧化或黑影遮缺。
- 背景不露內嵌矩形、雙層石台或明顯拼貼邊。背景過渡不得侵入角色，不能靠整圈光暈／投影假裝融合。
- 光向、明暗及色溫符合原場景；允許合理反射光與輔光，不為統一而改掉原卡配色。
- 原有深色毛髮不等於缺陷；先排除祖先 opacity/filter 或遮罩壓暗，不以過度增艷補償。

## 3D 層次與接觸
先依實際姿態定義遮擋關係，不套固定圖層順序。首頁通常為背景 → 地面／提示承接面 → 跨框爪尾；收藏外框與操作提示框須分清。
只有角色跨框，石台、花木與矩形底圖不能一起壓到提示前。卡線不得透過尾巴或腳掌實體；角色自然空隙仍可露底。
逐腳檢查應承重的接觸面，不以圖片外框猜位置；微移保持比例，不留可見懸空縫，也不讓腳陷入過深。躍起腳不強改為落地。
待機和提示態都需合理承接。陰影只在合理接觸處，方向與場景一致，不遮毛髮或代替缺失輪廓。
放大或微移後重驗爪尾、卡框、文字與寶珠；裝飾層不攔截點擊。

## 審查與完成
至少查看窄手機、一般手機、平板（可用320／390／768px），包含待機與提示；相關觸控、鍵盤焦點及原目的頁另按改動檢查。放大近照與實際顯示均看；程式通過不替代視覺判斷。
每項只記：未驗證、未通過、代理實測通過、業主接受。依既有授權可自行審查及退修，不冒充業主批准，不把未測項勾過。
保留「部位—問題—原因證據／假設—局部操作—前後證據—結論」。不達標中間稿自行處理，不反覆交使用者代驗。未看尺寸不能聲稱全裝置通過。
明確區分候選、本機接入、本機通過、提交、推送、正式部署。依 AGENTS.md 與本輪明確授權提交；既有失敗如實保留，例外不泛化成永久放行。
技能更新不代表作品通過，也不保證永不出錯；只有實際驗證有效的做法才回寫。
