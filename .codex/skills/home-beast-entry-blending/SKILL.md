# 首頁神獸入口視覺融合

這是工程視覺技能，不是命理運算技能或權威來源。只處理本次點名入口；開始前列出必要檔案及允許變更，先查 Git 差異，保留其他工作。功能、API、命理來源、文案及其他卡片保持凍結。新增範圍須有明確授權，不因本技能自動美化全站。

## 核實素材

依指定集合查正式神獸卡（四大神獸／二十八宿、成獸／幼獸），確認卡 ID、form、原圖及實際 renderer。不能猜同名圖、拿戰鬥姿勢替代本體或生成新獸。只有確實無法判定時才詢問。

已核對的來源鏈（每次仍檢查當前程式）：

- `app/star-beasts/page.tsx` → `components/battlefield/CatalogBeastCard.tsx` → `BeastCardFace`／`components/battlefield/BeastCardTile.tsx` 的 `ART_V2`；瀏覽器 `currentSrc`／`srcset` 可再核對實際顯示。
- 玄武：`cards/beasts/guardian-xuanwu.ts`，`beast_g_xuanwu`，正式 front 為 `public/beast-game/front/guardian-xuanwu.v2.webp`。
- 二十八宿心月狐：`cards/beasts/xin-yue-hu.ts`，`beast_a05`、`ADULT`，正式 front 為 `public/beast-game/front/adult-05.v2.webp`。不是幼子、四大神獸或其他狐狸。
- 不因資料檔另有 high 路徑就認定它是目前卡面；優先核對 renderer 的覆寫映射。

## 構圖與邊界

保留完整本體、原色與比例，使用 contain 等比呈現，不裁角色、不拉伸、不加改色濾鏡。原場景一起融入入口；可局部調整卡底與環境外緣的明暗銜接，保留寬鬆環境，四周略弧或自然不規則，消除明顯矩形內嵌圖卡。不要沿本體刻意摳形，不造聚光暈圈或規則橢圓相框。遮罩須避開角色細節，逐張確認，不能照搬同一遮罩而切掉尾巴或頭部。

外卡沿用首頁既有尺寸規則。先量測畫面順序的上下鄰卡，再調內部圖片比例及間距；不得為放大圖像撐長本卡，更不得修改鄰卡湊齊。尺寸規則在 `app/globals.css` 的 `--home-entry-min-height` 等入口規則；不要將某次 240／264px 實測值硬碼為全站規格。

標題、文字及裝飾是否移除，依當次授權。玄武曾獲准移除「生」小方塊並置中標題，並不授權其他入口刪字或移除標籤。按鈕文案與互動保持；圖片使用裝飾語義及 pointer-events:none，避免攔截操作。

## 預覽與檢查範本

先本機預覽，再依業主定稿及專案發布流程處理。報告至少包含：

```text
入口／批准視覺範圍：
必要檔案／原有未提交工作：
神獸集合、卡 ID、form、renderer 原圖：
各視窗：上卡 寬×高／本卡 寬×高／下卡 寬×高
完整本體、比例、原色、環境邊緣：
標題／圖／按鈕是否重疊，文字是否完整：
手機點擊、平板鍵盤 Enter、目的頁、瀏覽器錯誤：
本機近照與含上下鄰卡對照的絕對路徑：
檢查結果／未驗證項目／未提交或發布狀態：
```

至少涵蓋窄手機、一般手機及平板（本案曾用 320／390／768／1024px）。比較實際 bounding box；標題置中需量文字範圍，僅量容器可能漏掉內層 flex 對齊問題。人工看近照與鄰卡對照，確認上下左右都自然、角色清楚完整。入口可進入不代表後端生成或命理功能已全部通過。

參考已驗證實例：`app/music-entry.module.css`、`reports/beast-game/home-music-xuanwu-preview-2026-11-04.md`，以報告最新段落及即時 Git 狀態為準，前段是設計過程，不是全部有效規格。

提交發布遵守專案 `AGENTS.md` 與當次授權。只包含批准檔案，分開新卡預覽；測試失敗如實記錄，不擴修其他命理功能。任何既有命理檢查例外或朱雀 AI 圖片例外都不能由本技能泛化到下一輪。部署排隊不算成功；發布完成需核對 origin/main、部署終態、公開手機畫面與入口，最後執行 `git status --short --branch`，如實保留並報告其他未提交工作。

## 2026-11-05 定稿：原卡清晰、接地與觸碰引導

後續業主點名入口可依此方式製作；不自動批次修改其他卡。標題常駐，原圖等比，提示只在 hover（有滑鼠）、active 或 focus-visible 顯示，保留原連結與開啟流程。

- 讀取 computed style 檢查圖與祖先的 filter/opacity；首頁曾套 saturate(0.38)，須只在指定入口解除，不能以過度增艷補償。
- 以腳掌實際接觸面對齊提示上緣，不以圖片 bounding box 或石台邊框猜測。前景爪尖可搭進上緣，但不遮文字；圖片不攔截操作。
- 腳掌、爪尖、毛髮保留不透明；淡出只處理外圍場景與腳下石面，避免硬裁切或霧化爪尖。各角色須逐張核對，不照抄百分比。
- 背景石台承接腳掌，待機與提示顯示兩態皆不可懸空、雙層石台或出現人工橫線。
- 角色一律用既有正式原卡。只有業主明確批准背景生成才可補景，生成物僅為背景並記錄來源，不生成或替換角色。
- 驗收需含原卡對照、手機窄/一般與平板、待機/按住/鍵盤提示、原目的頁與文字不遮擋。保存實測範圍，未發布不得稱已上線。

業主追加偏好：點名下一張入口後，代理可依主題自行選擇合適的現有神獸並直接套用此規範，展示成果後依回饋微調，不再先詢問選獸。這不授權修改未點名入口。

八字牛金牛預覽教訓：背景明度不同會露出矩形內圖，先對齊背景明度，不能以擴大淡出犧牲牛角、耳尖或蹄部。每張原圖先定位角色最外輪廓，遮罩不透明範圍必須涵蓋它；尺寸模擬通過不等於視覺驗收完成，必須實際查看截圖後才報完成。

## 最低視覺驗收基準（2026-11-05 業主定稿）
八字首頁牛金牛幼子定稿為後續入口最低基準：原色與輪廓清晰；背景無矩形拼貼接縫；蹄/腳掌與石面有連續承接、不懸空；毛髮、角與爪尖不被遮罩霧化；標題常駐，觸碰提示不遮字，原功能不變。參照 reports/beast-game/home-bazi-young-2026-11-05.md。每張使用自己的接觸面與輪廓判定，不照抄座標或遮罩。未達此基準先細修，不以程式測試代替人工視覺核對；規範不代表保證永不出錯。

業主用語「修圖技能檔案」即指本技能：首頁神獸原卡與背景融合、原色/腳掌/接地/觸碰提示驗收。沿用本檔，不另建同義技能或降低八字定稿基準。

## 點名神獸即查用
六十張既有神獸的名稱、形態、正式圖路徑與原卡檔見 [神獸卡索引](references/beast-card-index.md)。業主說「修圖技能檔案＋神獸名稱」時，按索引取現有本體/幼子/四大神獸；形態依當輪明示或已確認上下文。連到原卡技能資料，不複製或重寫遊戲技能。依指定入口套用本技能，逐張校正背景、輪廓與接地，不將單一遮罩當成六十張通用遮罩。若入口未明確且上下文不能判定，才補問位置。

## 持續補強（業主批准）
每輪驗證有效、符合業主定稿方向的改進，主動回寫本技能或相關參考，不需重複詢問；記錄觸發問題、適用條件與實測證據。新規範不得降低八字定稿基準，不把未驗證嘗試、單張座標或主觀「更好」當通用規則。改進只影響後續授權工作，不自動批次修改其他卡片。

## 不得降低或偽造的驗收門檻（業主再次確認）
- 八字已批准定稿是最低標準；低於基準的呈現不得標記通過、不得作為完成版本提交發布。
- 明顯拼貼方框、接地不合、遮罩霧化角色、色彩失真、遮字或操作退步，任一存在均保留未通過狀態並細修。
- 禁止為趕進度降低檢查條件、刪除失敗證據、自動勾選通過或把未測項寫成已通過。程式測試不能代替視覺核對，已寫入規範也不等於驗收完成。
- 改善須有原卡與定稿對照、對應尺寸截圖及實際檢查結果後，才納入後續標準；未知或未完成如實記錄。
