日期：2026-11-03。範圍：`/ghost-asura`，不是 `/ghost-asura/skill` 追問頁。

## 測試環境與操作

命令：`node tests/ghost-asura-homepage-stability.e2e.mjs`。最終結束碼 0。

使用全新隔離 Chrome headless profile，390 × 844 起始手機 viewport，再切換390／320 × 740。沒有使用客戶分頁或儲存內容。選親朋好友、民國79年5月20日、男性、未時；共用表單將未時轉為既有13:30。之後改21日及22日驗證重算、逾時與重試。

生日用原生 input setter 與事件填入；按鈕與摺疊以可見座標點擊、檢查是否被遮擋。不是實體手指觸控、iPhone Safari或真機發熱測試。

## 結果

- 本機首次 API 回應約751ms；回應到結果 ready DOM 約17ms。這是本次單一電腦樣本，不是所有手機效能保證。
- 390px、320px 全頁均無橫向溢出；結果摺疊能展開與關閉，零延遲 timer 事件迴圈探針四捨五入為0ms。
- 兩次不同生日讀盤後，各只有1個粒子 canvas。靜置4秒後待執行 rAF 均為0，追蹤到的 Asura timer 數由2降為1，未隨重算增加。
- 第二次改資料先清除舊結果，再顯示新結果；請求順序與生日吻合。
- 將一筆真實 API 回應延遲35秒送達前端，未改答案；產品30秒逾時後解除忙碌狀態，表單仍可用。手動重試成功，延遲回應不使畫面退回等待或觸發額外請求。
- 全程共4筆讀盤請求，沒有自動重送。每次正常送出保留至少7秒間隔，未修改限流器。
- 點本頁回首頁連結完成同一文件內的客戶端換頁（非整頁重載）。強化測試以原阿修羅canvas物件的 `isConnected` 核對離頁清理，結果為0個仍連接、被標記的Asura timers=0。目的首頁可有自己的canvas及rAF，不能把全站canvas/rAF都必須為0當作本頁清理標準。
- 全程無未捕捉前端例外。

## 粒子畫布量測與限制

390px結果頁 canvas backing 為390 × 6234，約243萬像素；CSS同尺寸，main約6234.97px高。320px第二份結果為320 × 6535。這表示現行畫布仍覆蓋整個長頁，不能據此直接斷定它是手機停頓原因。已將量測交由效果維護者覆核，本輪未改canvas幾何或刪除效果。

Timer／rAF追蹤為測試頁內包裝瀏覽器排程API，timer用建立時呼叫堆疊是否含Asura／Particle篩選；它能補充離頁與兩次重算證據，不代表已完成所有記憶體洩漏、音訊實聽或長時間真機測試。沒有使用CPU節流，本次結果不能代表低階手機耗時。

本QA只新增測試與報告，沒有修改產品公式、來源或放行條件，也未提交／發布。

後續強化反例：等待5月22日讀盤逾時後，改5月23日手動重試；以新卡正文逐字比對，確認5月22日晚到回應不能覆寫5月23日結果。最終完整複驗通過（API約39ms、回應到ready約19ms，為暖機本機樣本）。測試也補上等待控件完成渲染，避免腳本先於時辰選項出現就點選。

## 首頁補接三步引導後的實際驗收

同日補接版執行 `node tests/ghost-asura-homepage-stability.e2e.mjs`，結束碼0；本段不是技能檔頁驗收，而是使用者實際入口 `/ghost-asura`。

- 已知時辰真實讀盤完成後出現 `[data-asura-conversation]`，未自動發送追問。
- 390px實點「看懂現在的解讀」得到第1步結論；320px實點「看依據」第2步與「看行動提醒」第3步。三步均成功，按鈕列表、答案、每輪scopeNote均逐字對上真API；結論不能直接跳行動，第三步完成後只剩主題切換。
- 每一項依據對回同份讀盤的引用、卡片ID、名稱和柱位，沒有前端補造來源。
- 對話區與全頁在390／320px均無橫向溢出；原有結果摺疊仍可點選展開收合。
- 另送「看過去」並延遲其真回應1.5秒，途中改生日，結果和對話區立即移除；舊回應抵達不會恢復舊對話。新日期重新讀盤後對話歷史為空。

- 本次首個API耗18,788ms，回應到ready DOM為21ms。這是本機開發環境單次首請求紀錄，不能略去或用前幾輪暖機數據代替，也尚不能歸因為手機渲染問題。原本30秒超時上限仍保留。
