# 指定延伸入口：既有技能檔命盤核對放行

## 範圍

業主於本輪先要求撤回額外命理改動，已恢復來源登記、原始公式及舊審查檔；之後明確批准老師判讀、喜用補強、配對紅鸞依既有八字與紫微後端核對結果放行。本文件記錄後一項限定授權，不解除其他卡片凍結。

## 實作

- 新增 `lib/bazi-reviewed-output.ts`，沿用 `assertThreeInOnePassed` 核對真正的後端結果、四柱、順序及命盤指紋；來源登記各狀態原樣保留。
- 老師兩個解讀 API 先接收原始出生資料、完成既有後端核對，再回傳解讀。不使用前端的通過標記或前端命盤。
- 八字 API 的台灣、國曆、精確時辰輸入，核對回傳四柱與既有結果一致後才附加放行狀態；其他輸入或核對失敗保留原有基礎命盤，不臆造時辰。
- 配對兩人都核對通過，且實際補強資料的四柱逐一一致，才開放補強與紅鸞。任一人未知時辰，即使來源狀態日後改變仍不開放上述延伸。
- 外部生成仍由原有停用設定阻擋；不修改公式、卡片數值、逐項神煞來源狀態。配對快取仍為原有五分鐘機制，本輪更新快取版本鍵，不宣稱每次命中快取都重新排盤。
- 健康與功能檢查分開呈現「指定入口放行」及「原始來源稽核」。未將來源待核改成 VERIFIED。

## 驗證

- 八字核心 81 項、紫微 318 項加核心 37 項、八字紫微交叉 104 項通過。
- 兩種老師 API 實際 localhost 請求均回 200、有解讀及命盤指紋；正常配對有補強與紅鸞，未知時辰沒有這兩項延伸。
- `bazi-reviewed-output`、`bazi-reading-provenance`、`bazi-reading-boundary`、`match-reviewed-output` 測試通過；包含錯誤指紋、不同四柱、缺時辰、偽造前端旗標及無舊結果回退。
