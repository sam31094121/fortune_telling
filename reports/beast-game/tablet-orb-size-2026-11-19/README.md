# 跨裝置盤面尺寸與文字列

重現：768×1024及1366×768，一隻與兩隻盤面尺寸不同。大螢幕原本使用block外殼最小高度作預算，單隻武器高度和手機限定隱藏的狀態／援助框也影響版面。修正：hard45使用實際區塊量測及固定五欄基準預算，排除自動留白；平板也使用flex排版；戰鬥狀態文字僅供讀屏，支援結果與攻擊說明在戰鬥隱藏、說明展開時可看。單隻大螢幕另留武器高度。

驗證：768×1024、1024×768、1366×768、320×580各一至五隻，共20組開場排列，盤面尺寸一致、無橫向溢出、卡片與武器在視窗內。獨立訪客測試，沒有出招或客戶收藏操作。型別通過；防抖與建置結果待補。仍依業主要求留本機待合併發布，未推送。

建置通過（既有警告保留），八種高度靜止與捲軸切換均零位移。320×580與1366×768另外逐一驗證整頁scrollHeight不超過視窗高度，無需上下捲動；此為瀏覽器尺寸模擬，非所有實體裝置保證。本輪未重跑全站健檢，正式發布前仍需核對。

## 少人放大補正（同日後續，取代上述僅尺寸一致的驗收結論）

業主回報筆電兩、三、四隻依然小。原測試只檢查盤面一致與不重疊，未檢查少人是否真正放大。實際原因為固定140／120／110px上限、共用剩餘高度限制，以及橫向卡圖仍使用方形高度；武器列另有一份相同舊上限。

修正：移除卡片及武器列的舊上限，共用可用空間欄寬；兩至四隻依實際卡圖比例排版，圖像仍contain。橫向筆電一般敵列以64px完整縮圖呈現，把省下高度交給我方；盤面預算不隨人數變化。單隻左右入口延伸到平板與筆電，修正右側入口壓卡及底部額外武器列占高。高於960px的大螢幕亦使用同一個hard45量測流程。

筆電1366×768實測卡寬：一隻279px，兩／三隻176px，四隻133px，五隻105.59px；盤面皆345×393.75px。兩／三隻約增加67%，四隻約增加26%。高度不足時兩隻不會強行鋪滿全寬，不拉伸或縮小寶珠。新增少人卡寬至少較五隻增加15%的筆電斷言，以及單隻不小於兩隻的檢查。

已完成六種尺寸各一至五隻：390×844、320×580、768×1024、1024×768、1366×768、1920×1080；每組檢查固定盤面、不捲動、卡片及武器對齊、滿能量入口顯示不改盤面、單隻兩側至少10px間距。筆電另實際重新整理五組，尺寸保留。結果見各growth目錄。橫向平板首次在武器目錄尚未載入時測得0個按鈕，見landscape-growth失敗記錄；測試改為等待真實目錄載入後仍要求完整按鈕數，landscape-growth-retry通過，未放寬對齊條件。

防抖八種高度均零位移；神獸公平性核心194項、客戶流程9項及1000場抽樣通過。health-first.json如實保存首輪63/67：原兩項豁免失敗、本人神獸入口逾時、最後敵方大卡靜態守門僅接受const宣告而拒絕let。入口單獨重測通過；守門改成接受兩種宣告，仍要求相同大卡預算判定，並由實際跨人數／重載／防抖測試驗證行為。最終健檢與建置尚待下方補記。
