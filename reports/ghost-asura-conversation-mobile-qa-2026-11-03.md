# 阿修羅引導追問：獨立手機尺寸瀏覽器驗收

日期：2026-11-03。目標：本機 `/ghost-asura/skill` 新增的引導追問區塊。

## 方法

執行 `node tests/ghost-asura-conversation.e2e.mjs`。使用獨立新建的 Chrome headless 暫存 profile，320 × 740 手機 viewport，合成資料：1990-05-20 14:00、男、國曆、台灣時間。測試結束關閉自己的瀏覽器並清理該暫存 profile，不使用客戶分頁、收藏或儲存資料。

日期／時間以瀏覽器原生 setter 及事件填入；性別、送出、追問正常流程以可見座標點擊並檢查遮擋。快速點擊反例以同一按鈕連續呼叫測試重入。所有內容來自實際本機後端；測試僅延遲一筆真實回應送達前端，不製造答案。

## 最終執行結果：通過

- 真實讀盤成功後才出現追問區，未自動發送追問。
- 「看懂現在的解讀」：present / summary / READY。
- 「看過去」「看現在」「看未來」：各主題 summary / READY。
- 「看重點」「看白話」「看行動提醒」：future 的 summary / why / action 均 READY。
- 每次畫面答案與該次真實後端 answer 逐字相等。
- 歷史最多保留六輪。
- 320px 時文件無橫向溢出，面板左右邊界均在 viewport 內。
- 快速連點三次只送出一次請求。
- 真回應延遲期間改生日，舊結果與追問區清空；舊回應抵達後不會重新顯示，結果維持 idle。
- 全程未捕捉的前端例外為零。

最終命令結束碼為 0。首輪曾因測試等待函式嘗試序列化 DOM 物件而失敗；已將測試條件轉為 Boolean，並給首次 hydration 等待時間，重跑以上完整流程通過。沒有因此修改產品程式。

## 邊界

這是 Chromium 手機尺寸模擬，不是 iPhone Safari/WebKit，也不是實體 Android／iPhone。未測真機發熱、鍵盤觸感、音效與長時間耗電；不宣稱全部品牌真機通過。此結果不解除其他既有來源稽核或專案發布門檻。

## 三步引導更新後複驗（同日，取代上方舊選項流程）

使用同一條可重跑命令與合成資料，更新測試後再次完整執行，結束碼 0：

- 現在：結論 → 依據 → 行動，三步均 READY。
- 切換過去：從第1步結論重新開始，再依據、行動，三步均 READY。
- 切換未來：從第1步結論重新開始；依據步為 UNAVAILABLE 且 basis 空陣列，明示沒有可對應的印記依據，不編補；第3步是既有整體行動提醒，READY，不冒充特定未來時段的推導。
- 每一步的數字、主題、intent、答案、限制說明與按鈕列表均逐項對應真實 API 回傳；第1步不能直接跳行動，第3步完成後只提供其他時段重開，不再無限重複同一意圖。
- 每個存在的依據項逐項核對同次原始讀盤的 guidance 引用，以及實際存在的卡片 ID、名稱與柱位。沒有依據時斷言 UNAVAILABLE。
- 六輪歷史上限、320px 全頁／面板無橫向溢出、快速三點只送一次、換生日後延遲舊回應不恢復、無未捕捉錯誤均通過。

新增正文、逐輪限制與步驟的穩定 data 屬性由前端協作者提供，本 QA 只調整 E2E 及本報告，沒有修改產品運算或來源政策。

## 連線穩定性複驗（同日）

同一 E2E 增加傳輸故障注入，最終完整重跑結束碼 0。請求間隔至少7秒，以遵守正式環境每分鐘10次上限；沒有改動限流器或替測試增加豁免。

- 初次讀盤：以 Chrome CDP 切離線，送出失敗會顯示錯誤並恢復表單；回網後不自動送出，手動按「開啟戰局」才取得真實讀盤。
- 追問：離線失敗保留既有歷史並恢復選項；回網沒有自動重試，手動點原選項成功取得真回應。
- 背景情境：使用 CDP 的 frozen → active 模擬瀏覽器生命週期暫停與恢復，歷史不變且沒有額外請求。這不是手機切 App 真機測試。
- 逾時：將一筆真實後端回應延遲35秒送達前端，未改回應內容；產品約30秒超時後恢復選項且沒有自動重送。手動重試成功，先前延遲的回應抵達後不覆寫或重複加入歷史。
- 原三步引導、六輪歷史上限、320px不溢出、重複點擊防重送、改生日隔離舊結果及零未捕捉例外全部再過。

首次穩定性測試的逾時步驟在尚有協作檔案更新的期間約5.7秒提前出現一般錯誤，沒有據此宣稱產品故障或通過；待元件完成、加入請求節流後，完整複驗通過實際30秒等待與晚到回應隔離。測試沒有修改資料來源、答案或公式。
