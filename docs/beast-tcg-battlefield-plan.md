# 60 神獸卡牌戰場改版計劃

編製日期：2026-09-06。交付狀態：本次計劃案完成；以下是待執行工期，不是已完成的開發紀錄。

## 1. 最新目標與適用範圍

依使用者最新文字，採實體 Pokémon TCG 的基本玩法結構，角色、美術、技能名稱與說明由本專案自製；以原有 28 本體神獸、28 本體幼子、4 紫微斗數四象為角色池。不是 Pokémon TCG Pocket，也不是目前本機的三隻隊伍速度對決。

最新要求「規則要一樣」優先於附件中「另建簡化規則」。因此不能把只完成牌庫、手牌和五格後備，宣稱為已完成相同玩法。目標是基本流程逐項對齊；自製五元素、角色技能和卡片尺寸等差異另列，不冒稱所有規則完全一致。

附件的 1:1 卡槽取代先前 63:88 的顯示規格，先改戰場，保留原美術檔案與 cardId。這次是計劃交付，不直接再次改寫現行遊戲。

## 2. 必須先分清楚的「60」

官方介紹確認：每位玩家用自己的 60 張牌組，牌中包含生物、功能與能量等不同類別。[官方入門](https://parents.pokemon.com/en-us/trading-card-game/)、[官方組牌介紹](https://www.pokemon.com/uk/strategy/designing-a-deck-from-scratch)。

本專案現有的是 **60 種神獸角色**，並非每場必須各放一張的牌組。建議實作基準：

- 神獸圖鑑繼續固定 60 種，三類角色數量不变。
- 每位玩家組一副 60 張牌，可包含同一角色的多個合法副本；每個副本具獨立 instanceId。
- 另做五元素能量牌與原創功能牌，作為系統牌，不列入神獸 0/60 圖鑑。**此方案總卡種會超過 60，但神獸仍只有 60 種。這項需在第一階段定案。**
- 如果使用者要求所有卡種加總也只能 60，且全部都是神獸，就須另設資源機制；那會偏離標準 TCG，不能同時聲稱規則完全相同。
- 幼子對應基礎形態、成獸對應進化形態；四象的上場類型及額外獎勵代價另列明確卡面條件。不可直接套用目前「完成三場解鎖」來取代戰鬥內進化；收藏解鎖與場上進化是兩件事。

## 3. 官方規則對照與待確認項

採用固定版本的官方規則書作實作基準，建立逐條測試矩陣。已找到[官方規則書入口](https://www.pokemon.com/static-assets/content-assets/cms2/pdf/trading-card-game/rulebook/par_rulebook_en.pdf)；本次工具讀取完整 PDF 遇到網站驗證，故不把以下待核對項目標記為已完整查證。

| 規則範圍 | 要核對並落實的行為 | 舊版必須移除／修訂的行為 |
|---|---|---|
| 組牌與開場 | 60 張牌組、同名張數限制與例外、基礎角色、起手、重抽、先後手、獎勵牌設置 | 固定只選三隻即開打 |
| 回合 | 抽牌、準備操作、使用卡片、進化、撤退、攻擊與回合結束；先手限制 | 每回合双方同時選一次，靠速度排順序 |
| 能量 | 從手牌附著、每回合限制、招式需求、撤退支付與例外 | 共用能量自動 +1、上限 6 |
| 招式與能力 | 招式傷害、能力使用條件、弱點抵抗與特殊狀態 | 通用攻防相減、所有技能固定冷卻兩回合 |
| 場上進化 | 正確進化鏈、登場回合限制、保留／清除哪些狀態及附著牌 | 花收藏成長直接改變場上角色 |
| KO 與勝負 | 倒下時卡及附著牌去向、獎勵牌取得、無可用角色、回合開始抽不到牌及同時成立的結算 | 擊倒預選三隻便結束、80 回合一律平手 |
| 功能卡 | 原創物品、每回合限用類型、場地與附著物；逐類核對限制 | 僅六個泛用技能效果便稱完整 TCG |

五元素不是官方原有類型；保持空、風、水、火、地，將自製弱點／抵抗資料列為明示變體。角色能力不複製官方卡面文字；逐張由自己的神獸故事與技能表制定。

## 4. 戰鬥場位置與視覺

主題採「天地人和・星宿神壇」：中央為低對比的圓形石台與星紋，玩家側暖金、對手側冷青，用邊線與標籤辨識敵我；不讓背景光效蓋過卡片。第一版只做一個穩定場景，後續再加森林、水域、熔岩等皮膚。

手機直向配置：

```text
對手：牌庫數／棄牌數／獎勵牌數／手牌數
       □ □ □ □ □  對手後備
             ■     對手主戰＋HP／附著能量
          回合提示與交鋒區
             ■     玩家主戰＋HP／附著能量
       □ □ □ □ □  玩家後備
玩家：牌庫／棄牌／獎勵牌
       □ □ □ …    玩家手牌（橫向滑動）
          當前合法操作／結束回合
```

附件沒有獎勵牌區；若以標準 TCG 為目標，必須加入，不以隱藏的 SPECIAL 代替。場地牌作用區另行定位，不能與獎勵牌混用。

| 區域 | 格數／顯示 | 操作與資訊界線 |
|---|---|---|
| 主戰 ACTIVE | 每方 1 格，約 112–152px 正方形 | 最醒目；點擊看能力與合法動作 |
| 後備 BENCH | 每方 5 格 | 手機點手牌再點合法空格；不能任意免费交換主戰 |
| 手牌 HAND | 數量可變；每格約 76–96px 正方形 | 玩家可滑動；對手只顯示數量／牌背 |
| 牌庫 DECK | 每方 1 疊 | 顯示剩餘數，伺服器控制洗牌與抽牌 |
| 棄牌 DISCARD | 每方 1 疊 | 點擊查看公開牌，不一律在棄牌區藏住牌面 |
| 獎勵 PRIZE | 每方獨立區域 | 顯示覆蓋牌與剩餘數，依規則才能取牌 |
| 場地／附著牌 | 專用區或主戰詳情 | 清楚區分持續效果、附著能量與角色本身 |

所有卡槽 aspect-ratio:1/1；圖片不可拉伸。現有直式卡圖先產生正方形衍生素材，檢查頭、角、爪、尾與文字安全範圍；不能直接 cover 裁掉身體。保留原圖，必要時補背景；最後才使用已審查的方形版本填滿卡槽。

390px 手機五格後備須維持可點擊尺寸；320px 若不足，採可滑動後備列，不能縮小到難以點中。主戰詳情以底部面板展開；戰場不常駐完整故事或技術公式。

## 5. 素材取得與修改流程

使用者已授權沿用現有素材並取用外部可用素材，不再逐張重問許可。執行時依具體素材條款保存證據，這不是把未具名網站的所有檔案視為已取得授權。

| 用途 | 優先來源 | 處理方式 |
|---|---|---|
| 60 種神獸／本體叫聲 | 專案現有卡圖、去背圖、音源與來源清單 | 對應 cardId，產生方形縮圖；只播放玩家本體聲音 |
| 石台、岩石、地面與環境光 | [Poly Haven](https://polyhaven.com/license) 的 CC0 素材 | 選單件資產，下載適量解析度，調色與烘焙為輕量背景 |
| 卡槽、按鈕、狀態標記基礎件 | [Kenney](https://kenney.nl/support) 的資產頁及包內 CC0 授權 | 改成自有星宿風格，不拿官方角色／卡背來改色 |
| 補充聲音 | 現有署名清單優先，必要時逐件查來源頁 | 保留作者、條款、修改標記；BY-SA 改作仍按相應條款提供 |

順序：選樣 → 記錄來源／作者／授權版本／下載日期 → 保存授權檔與雜湊 → 修改 → 手機壓縮 → 實際戰場檢查 → 登錄可發布版本。素材授權不自動涵蓋網站 API 的呼叫條款；不必為取得幾張背景大量抓取整站。

本次已查來源平台的官方授權資訊，未聲稱已完成所有外部背景下載、修改或 60 張方圖加工。外部素材款項預算暫按免費 CC0 規劃；若需付費資產，列出具體品項和價格再安排。

## 7. 資料與工程底線

- cardId 是卡種；instanceId 是這場的一張副本。相同 cardId 可合法有多份，但每個 instanceId 同時只能位於一個區域。
- 進化牌及附著牌有明確父子關係和所有者，不能因退場遺失或重複複製。
- 對手手牌、牌庫順序、未公開獎勵不可先回傳前端再用 CSS 遮住。
- 牌庫與正式判定由伺服器保存與執行。選中卡片是本機 UI 狀態，不混入對手資料。
- 每次動作帶戰局版本與操作 ID，後端驗證目前操作者、回合、區域及限制；重送只能結算一次。
- 既有 `.tmp`／本機檔案不能代替 Vercel 的持久資料庫。沿用上一版已發現的部署門檻，先接雲端儲存與遷移驗收，再正式替換。
- 不清除舊收藏、不把舊成長點偷偷重置；舊規則戰局按版本結束或明確退回，不能中途套新規則。
- 官方基本规则逐條對照；每張自製卡的具體能力另測。戰場功能與規則是不同驗收階段。

## 8. 完成判定與回報格式

每階段回報：實際開始／結束時間、完成項目、測試證據、剩餘事項、下一步、估算變動理由。實際時間未執行前留空，不預填「完成」。

最終需通過：牌組合法性、起手與重抽、各區唯一性、合法附能／進化／撤退、先手限制、KO／獎勵／勝負、對手資訊不洩漏、斷線復原、收藏保存、60 種素材對應、手機觸控、桌面拖放、音源授權與角色一致。

Safari、Android Chrome、LINE WebView 至少各實機走一場；工具模擬 390px 不等於三種真機均已通過。測速以指定裝置記錄資產大小、首屏時間與操作延遲；建議目標首屏 3 秒內、點選本機回饋 100ms 內，需在實測後決定是否達標。

工期以固定種子至少 10,000 場及不同組牌／策略測試為基礎；保留樣本、版本與失敗案例，不把單一 AI 策略的勝率當成人類對戰保證。

**本次已完成：計劃案、戰場位置規格、素材取得流程、工期與前後順序。尚未完成：本計劃所列的新版戰場開發與正式上線。**
