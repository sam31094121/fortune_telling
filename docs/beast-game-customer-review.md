# 六十張神獸卡：玩法與公平性審查

更新：2026-09-05。本批交付「親手布陣＋自動對戰」體驗；可供客戶試玩，尚不能據此保證留存或所有陣容完全平衡。

## 客戶走法

1. 圖鑑按「我自己」，沿用本人出生資料找出本體神獸；資料不足才補填。使用既有八字日柱收藏對應，不猜時辰，不借用他人的已存神獸。
2. 進入組陣台，挑一張卡、預覽、親手確認放入前鋒／中軍／後陣。
3. 三席放滿、總氣不超過十二，再從成長中心已獲得的卡選一張押注。確認押注後啟陣，電腦三張實際開場牌依序入格；親手揭牌、觀看交鋒或略過至結算。

「看一張建議」只預覽，不自動填格、不自動開戰。卡圖沿用現有素材。本體二十八張、幼子二十八張、四象四張，各自獨立；前台五元素固定為空、風、水、火、地。

## 已修正與驗證

- 核心也檢查三席、唯一卡片與十二氣上限；玩家及對手相同。補位使用真正空出的格子。
- 一回合暈眩會阻止持有者一次實際行動；每張卡的限次技能獨立計算；朱雀加成給自己；守方反應使用守方資源。
- 開場先後手由種子決定，後手補牌、先手首回合不進攻均綁定實際先後手。
- 防禦以五成折算，減少多數攻擊卡在一點傷害、靠牌庫耗盡分勝負的偏差。
- 正常對戰種子由伺服器產生；對手押注在核心開戰前鎖定。重播只展示原場快照，不重複發獎或扣卡。
- 本人入口對已知／未知時辰、錯誤生日、農曆日期及舊時辰欄位進行檢查。三合一不通過時不顯示結果。
- 手機 375 × 812 驗收：預覽前不填格、手動放卡、換卡、超額鎖定、啟陣及結果；關閉預覽、清空與重進正常。桌面預覽也已檢查。不能替代 iOS／Android 真機驗收。

測試命令：`npm run test:beast-fairness`、`npm run test:star-beast-entry-api`、`npm run build`、`node scripts/screen-health-monitor.mjs --no-repair --mobile-first`。

公平性完整測試、本人神獸 API 以及神獸圖鑑路由已納入固定健康檢查。使用合成測試資料，不發獎、不改客戶收藏；規則失敗不會自動重啟服務。

固定樣本一千局（五百組陣容互換，涵蓋六十張卡）：先手勝 513、後手勝 478、平手 9，非平局先手勝率 51.77%，平均 10.42 回合。這是特定採樣下的回歸檢查；未窮舉所有組合，也未驗證高手最佳策略。

## 客戶接受度與下一批

這版的優點是入口短、選擇明確、每張卡都有用途；可作為試玩版。真正的接受度仍需觀察首次完成布陣的比例、首戰完成率、換陣再戰率及隔日回訪，不以內部評分當作客戶驗證。

收藏押注已串接：成長獎勵與對戰贏來的卡共用「我的神獸收藏」。勝利保留原押注並取得對手的一張；敗北扣掉自己的實際副本一張；平手不增減。解鎖成就保留，但已領且輸掉的成長卡不會重新發送。沒有卡的新客戶先引導完成探索或累計四次每日任務。

組陣在本機記住；清除網站資料後會消失，不能宣稱跨裝置同步或永久保存。這版仍是啟陣後自動對戰，尚未包含逐回合手動出牌、完整逐招戰鬥動畫或多人配對。

## 雙方揭牌與卡框統一

- 卡池仍為六十張，每場各選三張開場上陣。對手標示為電腦，不冒充真人。
- 入格、牌背和翻面都使用同一份 API 陣容，保留前鋒、中軍、後陣順序。動畫不另外抽卡、不重算勝負、不依輸贏換牌；核心依既有規則召喚補位與開場陣容是不同階段。
- 戰果在收到有效回應後先保存，動畫不控制發獎。關閉動畫會顯示既有結算，不能藉此逃避扣卡。尚無有效戰果的連線中斷不扣卡。
- 六十張卡池、出戰三席、放大預覽、揭牌共用卡框比例。卡名不拆行；放牌沿固定格子依序落下，不左右搖晃。牌背保留完整金邊，放大預覽保留完整原圖。
- 交鋒節錄只選既有紀錄；展開戰報可以看至最後回合，不再截斷為前六十筆。卡面標示「開場陣容」，避免把後續補位神獸混同為最初六張。
- 結算失敗顯示「待保存」，不宣稱已得卡或已沒收，且先封鎖下一場；可以重試同場保存，重開頁可恢復已收到的結算。
- 本批以 304 × 660、375 × 812 及 1280 × 900 瀏覽器尺寸驗收；六張牌和主要按鈕不溢出，翻面前後卡框座標與尺寸一致。完整戰報、同場重播、返回布陣、略過動畫皆已操作確認；不是手機真機測試。
