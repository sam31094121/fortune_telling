# 鬼魅阿修羅 - 前後端米其林分工制

**規則：後端算、前端顯。零邏輯交界，嚴格分工。**

---

## 🏗️ 整體架構

```
Landing Page（預告片首屏）
    ↓ [CTA 點擊]
/ghost-asura（資料填寫 → 後端運算）
    ↓ [API /ghost-asura/calculate]
後端運算引擎
  ├─ 八字命盤（bazi.ts）
  ├─ 紫微斗數（ziwei.ts）
  ├─ 特星神煞（shensha.ts）
  └─ 易經卜卦（iching.ts）
    ↓ [回傳 GhostAsuraCardResponse]
前端卡片（GhostAsuraCard.tsx）
  └─ 純視覺呈現（CSS + HTML 只照印）
```

## 🔴 前端紅線（禁止事項）

### ❌ 禁止這些操作

```typescript
// ❌ 不要運算
const analysis = calculateAnalysis(data); // 禁
const grade = Math.round(score * 100); // 禁

// ❌ 不要拼句子
const message = `你的性格是${element}，所以會...`; // 禁
const desc = "前綴" + data.desc + "後綴"; // 禁

// ❌ 不要生成文字
const options = items.map(i => `${i.name} (${i.level})`); // 禁

// ❌ 不要決定內容顯示邏輯
{isPillarImportant ? <div>{pillar.name}</div> : null} // 禁

// ❌ 不要修改後端資料
const processed = data.analysis.replace(/xyz/g, 'abc'); // 禁

// ❌ 不要自撰中文
<span>這是前端寫的句子</span> // 禁
```

### ✅ 只做這些

```typescript
// ✅ 直接照印
<div>{data.bazi.analysis}</div>

// ✅ 條件顯示（不改內容）
{data.ziwei && <section>{data.ziwei.chart.analysis}</section>}

// ✅ CSS 排版
<div className={styles.card}>{data.analysis}</div>

// ✅ 無障礙標籤
<section aria-label="四柱">
  {data.bazi.pillars.map(p => (
    <div key={p.name}>{p.stem}/{p.branch}</div>
  ))}
</section>

// ✅ 動態值（顏色、ID、timestamp）
<div style={{ borderColor: data.visual.themeColor }}>
  {new Date(data.meta.timestamp).toLocaleString()}
</div>
```

## 📋 後端數據契約

### 回傳結構（型別定義）

**檔案：** `/lib/types/ghost-asura-response.ts`

```typescript
GhostAsuraCardResponse {
  user: {
    name: string;         // 使用者輸入
    birthDate: string;    // YYYY-MM-DD
    birthTime?: string;   // HH:mm
  };
  
  bazi: {
    pillars: Pillar[];    // 四柱資料
    analysis: string;     // ⭐ 後端產出的話術
  };
  
  ziwei: {
    chart: ZiweiChart;
    verification: {
      status: 'VERIFIED' | 'MISMATCH'; // 與八字校驗
      message?: string;  // 如不符，說明差異
    };
  };
  
  shensha: {
    items: ShenShaItem[]; // 神煞陣列
    combo: string;        // ⭐ 整盤組合話術
    flowYear: {
      current: string;    // ⭐ 今年流年說明
      next?: string;
    };
  };
  
  iching: {
    result: {
      hexagram: number;
      name: string;
      judgment: string;   // ⭐ 爻位解讀（後端產出）
      guidance: string;   // ⭐ 人生指引（後端產出）
      psychology: string; // ⭐ 心理學視角（後端產出）
    };
  };
  
  teacherReading: {
    opening: string;       // ⭐ 開場白（後端產出）
    mainInsight: string;   // ⭐ 核心洞見（後端產出）
    lifeGuidance: string;  // ⭐ 人生指引（後端產出）
    closing: string;       // ⭐ 收尾寄語（後端產出）
  };
  
  visual: {
    themeColor: string;    // CSS color: "#d4af37"
    accentColor: string;   // CSS color: "#e63946"
    cardLayout: string;    // 'vertical' | 'horizontal'
  };
  
  meta: {
    timestamp: number;
    version: string;
    verified: boolean;     // 四柱驗證是否通過
  };
}
```

### ⭐ 標記的字段

這些都是**後端產出**的話術，前端**禁止修改**：

| 字段 | 來源 | 責任 |
|------|------|------|
| `analysis` | `lib/bazi/engine.ts` | 八字解讀 |
| `combo` | `lib/iching-shensha-combos.ts` | 整盤神煞組合 |
| `flowYear.current` | `lib/iching-shensha-flow-year.ts` | 流年提示 |
| `judgment` | `lib/iching-shensha-iching.ts` | 易經爻位 |
| `guidance` | `lib/iching-shensha-iching.ts` | 人生指引 |
| `psychology` | `lib/iching-shensha-onion.ts` | 心理學層 |
| `teacherReading.*` | `lib/ghost-teacher-persona.ts` | 老師人設話術 |

## 🎨 前端元件結構

### GhostAsuraCard.tsx（唯一的渲染組件）

```
Props:
  - data: GhostAsuraCardResponse (後端傳來)
  - isLoading?: boolean (載入狀態)

職責：
  1. 接收完整的 GhostAsuraCardResponse
  2. 決定哪些 section 顯示（{data.* && <section>}）
  3. 直接渲染所有文字（{data.xxx}）
  4. 套用 CSS 樣式（styles.xxx）
  5. 加入無障礙標籤（aria-label, role）

禁止：
  ❌ 修改任何文字
  ❌ 拼接句子
  ❌ 運算或邏輯決定內容
  ❌ 生成新的中文句子
```

### CSS 模組（GhostAsuraCard.module.css）

```
全權負責：
  ✅ 字體大小、顏色、對比度
  ✅ 間距、邊界、背景
  ✅ 響應式設計（手機 / 平板 / 桌面）
  ✅ 動畫、過渡、懸停狀態
  ✅ 列印樣式
  ✅ 無障礙（WCAG AA 4.5:1 對比度）

注意：
  - 所有文字顏色 ≥ 4.5:1 對比度
  - 響應式不破裂（mobile-first）
  - 尊重 prefers-reduced-motion
  - 支援列印（不印背景色）
```

## ⚡ 常見問題

### Q: 如果後端的話術過長，前端可以截斷嗎？

**A:** ❌ 不可以。後端已經決定長度。
- 如果需要縮短，告知後端修改話術源頭
- 前端只能用 CSS `overflow: hidden` 或 `max-height`

### Q: 前端可以國際化（i18n）嗎？

**A:** ❌ 不可以。後端應該回傳已翻譯的話術。
- 前端不應包含任何翻譯邏輯
- 多語言應在後端層決定

### Q: 如果資料為空，前端怎麼顯示？

**A:** ✅ 用條件渲染決定是否顯示，但不改內容
```typescript
{data.shensha && <section>{data.shensha.combo}</section>}
```

### Q: 前端可以加「點擊查看更多」之類的互動嗎？

**A:** ✅ 可以，但只決定顯示/隱藏
```typescript
{item.psychology && <details><summary>心理學視角</summary>...</details>}
```
不可以在 `summary` 內自撰文字。

### Q: 為什麼要這麼嚴格？

**A:** 
1. **可信度**：所有話術由後端驗證、有來源、通過檢查
2. **一致性**：不會出現不同前端顯示不同內容的情況
3. **可維護性**：修改話術只改後端，不需改前端
4. **可測試**：後端能完全驗證內容品質，前端只測視覺
