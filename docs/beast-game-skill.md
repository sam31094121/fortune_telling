## 一、這是什麼遊戲

《二十八宿・神獸決鬥》——從六十張神獸卡挑三隻布陣，與對手各出三席，
親手布陣及揭牌後，由核心自動推進回合並依終局規則判定勝負。

**六十張的組成（全部使用既有素材，沒有新造任何一隻神獸）**

| 二十八宿・幼子 | 28 | `star-beasts.json` 的 `youngDivineImage` |
| 二十八宿・成獸 | 28 | `adult-divine-v2` |
| 四象 | 4 | `four-guardians`（青龍・朱雀・白虎・玄武） |

## 二、客戶最常問的三件事（畫面上都要答得出來）

### Q1：對方是不是也放三張？

**是。雙方都是三席，規格完全一樣。**

揭牌儀式會把雙方六張牌並排蓋著，一起翻開——這不只是好看，
是讓「對手也擺了三張」這件事**被看見**，而不是靠文字宣稱。

### Q2：這是跟誰玩？

**目前是跟電腦對手玩。**

畫面上必須明講「電腦對手」四個字，儀式裡對手那一排也標示為「電腦對手」。
對手的三席是從同一個六十張卡池隨機抽的，用同一顆種子產生，可回查。

**禁止用電腦冒充真人。** 沒有做的東西就說沒有做——
這是「禁止作假」在產品層的意思，不只是數值不能作假。

### Q3：可以跟真人玩嗎？

**目前不行，而且畫面上要誠實標示「尚未開放」。**

真人對戰要做的東西見〈六、真人對戰（尚未開放）〉。
在那之前，任何「線上對戰」「與其他玩家對戰」的字眼都不得出現。

## 三、遊戲規則（唯一版本）

```
本命 30，打光就輸
牌組 20 張・起手 5 張・每回合抽 1
氣：每回合上限 +1（上限十）、回合開始補滿、當回合不保留
出戰三席開場就在場上，雙方合計最多十二氣且不得重複；不扣回合內的氣
站位有意義：前鋒先挨打，後陣被保護
對面清空 → 直擊本命
牌庫抽乾 → 疲勞遞增，避免無限僵局；仍可能平手
七階段：TURN_START → DRAW → SUMMON → ACTION → BATTLE → EFFECT_RESOLVE → TURN_END
```

**公平性（每次 CI 都量一次，不是宣稱）**

| 項目 | 做法 |
|---|---|
| 先後手 | 由種子擲，不是固定客戶先 |
| 後手補償 | 多抽一張牌 |
| 先手節制 | 第一回合不進攻 |
| 種子 | 伺服器產生，客戶端不能指定（只能重播） |
| 對手資源 | 本命、氣、牌量與玩家完全相同 |
| 固定樣本實測 | 一千局、五百組交換，先手勝 513、後手勝 478、平手 9；非平局先手勝率 51.77% |

此為固定採樣下的回歸檢查，未窮舉所有陣容，不能據此宣稱全面平衡或保證留存。

## 四、卡片規格（正統）

**比例 63 × 88 mm（0.716）**——實體集換式卡牌的通用規格，等同撲克牌 2.5"×3.5"。

唯一來源：`components/BeastCardFrame.module.css`
六十張卡池、出戰三席、揭牌儀式、放大預覽**四個地方吃同一份**，
任何一處自己另寫比例，`npm run test:beast-card-spec` 會擋下來。

- 卡池與出戰格用 `cover` 填滿圖窗；放大預覽與揭牌面用 `contain` 保留完整圖，牌背不裁掉金邊
- 卡內尺度用 `cqw`，同一張卡在手牌／三席／預覽是同一張的不同大小
- 名字條固定高度、過長省略，六十張並排時底部一定對齊
- 放牌不得讓版面跳動（操作列永遠佔位）

**三段式圖（手機不卡的前提）**
`thumbnail` 256w（26–35KB）→ `front` 720w → `high` 原圖 2.8MB
手牌與卡池只載縮圖，點「詳細」才載中等，高清只在原圖層。
加卡後重跑 `node scripts/gen-beast-card-art.mjs`。

## 五、要加東西時怎麼做

**加一張卡**
1. `cards/beasts/<slug>.ts` 照 `BeastCard` 寫資料
2. `lib/beast-game/registry.ts` 的 `REGISTERED` 加一行
3. `npm run test:beast-game`

驗證沒過就進不了正式牌庫（registry 真的會擋，不是印警告）。
**任何一支引擎都不用改。**

**加一個技能**
`cards/skills/index.ts` 加一筆，`effects` 只能用既有 13 種 EffectType。
Battle Engine 不認得任何技能名字（測試會擋），所以不必動它。

**禁止**：建第二套核心、每張卡一套戰鬥程式、技能寫死在 UI、
前端自行算勝負、動畫決定結果、為了新卡重寫核心。

## 六、真人對戰（尚未開放）

業主問：「如果跟真人玩，就是有同樣在線上的玩家在玩這一套遊戲，
可以把它列為技能檔案裡面嗎？」——列在這裡，但**還沒有做**。

### 為什麼現在還不能做

現有核心是**一次算完整場**（`playToEnd`）：伺服器拿到雙方陣容，
瞬間跑完二十幾回合，回傳完整戰報。這個設計讓「動畫不得決定結果」
成立，也讓同種子可重現——但它假設**雙方陣容在開打前就都知道**。

真人對戰不成立這個前提：對手是活人，會在過程中做決定。

### 要補的東西（做之前要先批准）

| 項目 | 說明 |
|---|---|
| 逐步推進 | `playTurn` 已經是一回合一步，可以接；但要能在中途等待對手輸入 |
| 對戰房間 | 配對、房號、雙方就緒才開始 |
| 即時通道 | WebSocket 或輪詢；斷線重連要能接回同一場 |
| 權威伺服器 | 每一步都由伺服器裁決，客戶端只送「我要做什麼」——**絕不能讓客戶端送結果** |
| 防作弊 | 客戶端不得知道對手手牌；種子與隱藏資訊只留在伺服器 |
| 離線處理 | 對手斷線、掛機、投降的判定 |
| 誠實標示 | 配對中要講清楚是在等真人，不得偷偷換成電腦 |

**最後一條是重點。** 很多遊戲在配對不到人的時候偷偷丟一個機器人進來，
還是寫「玩家 XXX」。那就是作假。要嘛等到真的有人，要嘛明講「換成電腦對手」。

### 現階段的正確做法

畫面上提供模式選擇，但誠實標示：

```
與電腦對戰      ← 現在可玩
與真人對戰      ← 尚未開放（不是「即將推出」，是真的還沒做）
```

## 八、戰鬥卡片技能（卡片對打）

> 口令：**「戰鬥卡片」** 或 **「卡片對打」**
> 說這幾個字＝沿用本節的演出架構補全，**不得另做一套戰鬥演出**。

### 這一節在管什麼（戰鬥儀式感）

從「牌蓋著」到「分出勝負」之間，客戶看到與聽到的每一件事。
包含揭牌節奏、神獸本體衝鋒、撞擊音效、三維演出。

**不包含**任何規則與數值——那些在〈三、遊戲規則〉，由後端 Game Core 決定。

---

### 第一條：演出不決定結果

**規格第十二條：動畫不得決定戰鬥結果。**

後端已經把整場算完（含勝負、押注結算），演出層只決定
「什麼時候把哪一段揭給你看」。快轉、跳過、自動翻、重播，
結果都完全一樣——**儀式感是節奏，不是機率**。

守門測試會擋住演出層匯入任何會決定結果的東西：
`playToEnd` / `playTurn` / `performAttack` / `computeDamage` / `resolveStake` / `Math.random`。

---

### 揭牌：一張一張，交替翻

```
你的前鋒 → 對手前鋒 → 你的中軍 → 對手中軍 → 你的後陣 → 對手後陣
```

順序寫在 `lib/beast-battle-fx.ts` 的 `REVEAL_ORDER`，測試會檢查它確實交替。

**預設手動。** 客戶按「翻開你的前鋒」，一張一張自己翻，節奏他決定。
按「➤ 自動翻牌」才切自動（間隔 620ms），隨時可以「↻ 改回自己翻」。

> 第一版是一個布林 `revealed` 控制全部六張，所以六張同時掀。
> 現在是計數 `revealCount`，每張卡自己判斷翻了沒。

每翻一張：那張卡依元素顏色短暫發光、播一次輕音、
中央顯示「現在翻的是誰的哪一席」與進度 n/6。

`prefers-reduced-motion` 時直接六張全開，不做逐張動畫。

### 神獸本體：五十六張立繪，衝過去對打

業主定調：「每一張都要生成牠本體的神獸跑過去對方的牌。」

**為什麼要另外生成**：`public/star-beasts` 的原圖沒有 alpha 通道
（實測 3 channels），是完整背景的插畫。直接丟進三維場景會變成
「一塊會飛的長方形插畫」，比不做更糟。

**產生管線**（`scripts/gen-beast-spirits.mjs`）

1. 把既有插畫餵給影像模型，要求「同一隻神獸、全身、衝鋒姿態、純黑背景」
   —— 以圖生圖是為了讓生出來的還是那一隻，不是另外畫一隻新的
2. 把純黑鍵成透明。黑底去背比複雜背景可靠得多，所以是
   「請它畫在黑底上」而不是「請它給我透明背景」
3. 縮到 512 高、轉 WebP
4. 存成 `public/beast-game/spirit/NN.webp`（成獸）與 `NNy.webp`（幼子）

**成獸與幼子分開生成。** 幼子用成獸的立繪就是拿大人的圖冒充小孩，
所以幼子有自己的提示詞（圓身、大頭大眼、短肢）與自己的參考圖。

```
28 成獸 ＋ 28 幼子 ＋ 4 四象 ＝ 六十張卡各自的本體
四象必須使用自己的去背立繪；不可把首宿的動物當成四象本體。
本次實玩發現四象對照錯置，專屬透明素材尚在驗收，詳見本體聲音技能檔。
```

卡片對應本體：`spiritArtFor(cardId)`。沒有立繪就退回卡面，不會開天窗。

```bash
node scripts/gen-beast-spirits.mjs --limit 28                    # 成獸全部
node scripts/gen-beast-spirits.mjs --young --limit 28            # 幼子全部
node scripts/gen-beast-spirits.mjs --young --only 13,20 --force  # 重生指定幾隻
npm run check:beast-spirits                                      # 檢查去背成功沒
```

**這支會花錢**（呼叫付費影像 API）。所以預設只跑 `--limit` 指定的張數、
已存在的檔案預設跳過、每一張都印出結果與檔案大小——跑到哪裡看得見。

#### 兩個踩過的坑，寫下來免得再踩

**一、檔案會肥到不能用。**
模型原始輸出一張 1.4MB，五十六張就是 84MB，違反手機優先憲章。
縮到 512 高轉 WebP：32.6MB → 1.9MB。三維場景裡本體最多佔螢幕一半高，
512 綽綽有餘，存原始尺寸只是佔空間。

**二、模型會無視「純黑背景」回一張白底圖。**
那種圖經過黑底去背之後背景原封不動，結果是**一塊白方塊衝過去**。
實測五十六張裡有三張這樣（13y／20y／21y）。

所以 **`npm run check:beast-spirits` 是必跑的，不是選配**——
它用「透明像素低於三成五」判定去背失敗。這種事不能靠肉眼看。

### 三維對撞

`components/BeastClash3D.tsx`：兩隻本體是三維空間裡的物件，
有透視、深度、旋轉；出手方衝過去，撞擊時閃光震動。
撞擊光用既有的 `lightning-impact-cc0.png`，不另做特效素材。

**效能紀律（太極憲章：手機優先 60FPS）**

- 場上永遠只有兩隻本體與一片光，不是六十個模型
- 不開陰影、不用後製
- 只在交鋒階段動態載入，演完就卸掉，不長期佔 WebGL context
- `prefers-reduced-motion` 直接不掛載，交給靜態版面

### 玩家本體聲音

戰鬥依 [本體聲音技能](beast-voice-skill.md) 播放玩家自己卡片的叫聲，
六十張對照與授權保存在 `public/audio/beast-voices/manifest.json`。
成獸、幼子及四象有各自的成品檔；叫聲依本體分類，不依元素硬配。
對手出手保留動畫，但不播放對手聲音。神話角色及部分本體使用擬音設計，
來源與加工方式詳列於 `public/audio/beast-voices/CREDITS.md`。

舊的 `cardSoundProfile`、`playClashSequence` 與太極三段式撞擊素材保留給舊功能；
本次戰鬥儀式已改用 `playPlayerBeastVoice`，不以泛用撞擊聲代替神獸叫聲。

#### 音效的紀律

- **固定啟用。** 戰鬥是要有聲音的，隨揭牌與交鋒直接播，不另設開關
- 播不出來就靜靜跳過（很多行動瀏覽器在使用者手勢前不准播）
- `prefers-reduced-motion` 只管動畫，不關聲音
- **不 await、不擋流程**——音效永遠是加分項，壞掉不能影響遊戲進行

### 加新卡時要做什麼

1. 照〈五〉加卡片資料
2. `node scripts/gen-beast-card-art.mjs` 產三段式卡圖

不能只新增卡片資料就宣稱本體及聲音驗收完成。

### 三局逐組結算（核心 1.3.0）

前鋒、中軍、後陣各自單挑，重置生命及技能次數，共用原傷害與技能引擎。
速度高者先手，同速依種子決定。單挑無牌庫或補位，抽棄牌效果沒有目標；
百次行動未分勝負則平手。每組約六秒演出，再停留兩秒顯示局勝負與累積比分。
第二組後若已二比零，第三組自動揭開；一比一則關閉自動翻牌，
讓客戶親手揭開第五、第六張。三局總比分決定整場與押注結算，同分退回押注。

## 九、遊戲核心（口令「神獸卡遊戲」）

> 原本獨立在 `docs/three-core-cross-validation-skill.md〈十〉`，已整併進本檔。原文保留。

#### 一句話

一個遊戲核心、一套卡片格式、一套技能系統、一套效果系統、一套戰鬥規則。
**以後新增神獸卡＝新增資料，不是重寫程式。**

#### 架構

```
cards/beasts/*.ts     卡片資料（一張一個檔）
cards/skills/index.ts 技能登錄中心
        ↓
lib/beast-game/
  schema.ts    卡片格式＋品質驗證（不合格禁止進正式牌庫）
  elements.ts  五元素（接平台既有對照，不另立第二套）
  registry.ts  卡片登錄中心
  effects.ts   效果核心（13 種 EffectType，唯一會改狀態的地方）
  battle.ts    戰鬥核心（傷害公式、技能觸發、出手順序）
  turn.ts      回合核心＋牌組系統（七階段轉移表、種子亂數）
  balance.ts   平衡評分（Power Budget／BALANCE_WARNING）
  index.ts     BeastCardGameCore 對外唯一入口
```

守門：`npm run test:beast-game`（156 項）、健檢第 23 項

#### 怎麼加一張卡

1. `cards/beasts/<slug>.ts` 照 `BeastCard` 寫資料
2. `lib/beast-game/registry.ts` 的 `REGISTERED` 加一行
3. 跑 `npm run test:beast-game`

驗證不過就進不了正式牌庫——這是真的擋，不是印警告。
**任何一支引擎都不用改。**

#### 怎麼加一個技能

`cards/skills/index.ts` 加一筆，`effects` 只能用既有的 13 種 EffectType。
Battle Engine 不認得任何技能的名字（測試會擋），所以加技能不必動它。

#### 幾條硬規則

| 規則 | 實作位置 |
|---|---|
| 前端不准自己扣血、算勝負 | 全部在 `battle.ts`／`effects.ts`，純函式無 React |
| 動畫不得決定戰鬥結果 | `GameState.timeline` 先算完，前端照著播 |
| 七階段不得跳關 | `turn.ts` 的 `NEXT_PHASE` 轉移表，違規丟例外 |
| 同一招不得無限放 | `usesPerBattle` + `SkillUsage` |
| 稀有度不等於絕對戰力 | `rarityIsNotPower()`，預算帶必須重疊 |
| 手牌不得載高清圖 | 三段式 `thumbnail`／`front`／`high`，測試比對檔案大小 |
| 同一場要能重現 | 種子亂數，同 seed 同結果（可回查客訴） |

#### 第一階段實測（6 張卡）

```
角木蛟 SR 296  亢金龍 SSR 296  氐土貉 N 277
房日兔 R  275  心月狐 R   299  尾火虎 SR 321
稀有度重疊：N最高277 vs R最低275／R最高299 vs SR最低296／SR最高321 vs SSR最低296
縮圖 26–33KB（原圖 2.8MB），手牌只載縮圖
```

#### 過程中被自己的檢查抓到的兩件事

1. **稀有度變成絕對戰力**：第一版數值排出來 SR 最低 310 > R 最高 286，
   `rarityIsNotPower()` 直接報錯。調整 SR 下修、R 上修才通過。
2. **常駐被動把預算炸掉**：被動用 `duration: 99` 表示常駐，
   技能分算出 588，比整張卡的數值分還高三倍。改成邊際遞減並封在四回合。

兩件都不是「感覺怪怪的」，是算出來的數字報錯。這就是第十九條要的效果。

## 十、本體聲音技能（六十張各有自己的叫聲）

> 原本獨立在 `docs/beast-voice-skill.md`，已整併進本檔。原文保留。

本檔是 `beast-game-skill.md` 的聲音規格，沿用同一套戰鬥核心。

### 使用者定調

- 六十張卡各有固定本體音色：28 成獸、28 幼子、4 四象，以卡片 ID 對應，不根據對手或勝負換聲。
- 只播放玩家自己上陣的神獸。電腦及線上對手的叫聲不播放；對手的攻擊、受擊及勝負動畫照常進行。
- 叫聲符合本體：虎是虎吼、鳥是鳥鳴、鼠是短促吱聲。龍、朱雀等神話角色可以用授權底材設計音色，但不得稱作真實神獸錄音。
- 不把雷聲、撞擊聲當成神獸叫聲，不將一段吼聲套到所有卡片。不以四象分組代替本體分類，例如朱雀組裡的馬仍用馬類聲音。
- 同種成獸與幼子可使用相同錄音底材，但成品音高、長度與空間感應分別處理。同一時刻只保留一個玩家本體聲音，避免疊音。
- 預設啟用，沒有要求客戶另開的音效開關；由揭牌的使用者操作啟動聲音。瀏覽器拒絕播放時，不阻斷戰鬥。
- 揭牌及出手時觸發自己的卡片叫聲，退出／略過會停止播放。聲音不參與傷害、技能、比分、押注或勝負計算。

### 資料與授權

- `public/audio/beast-voices/manifest.json`：每張卡的素材來源、加工參數及對照。
- `public/audio/beast-voices/CREDITS.md`：原作者、原頁面、授權連結、加工說明；需要相同方式分享的成品聲音保留相應授權。
- `scripts/build-beast-voices.py`：可重現的剪輯、音量整理與音色加工。
- `lib/beast-battle-fx.ts`：卡片聲音路徑、玩家側播放守門與單聲道來源管理。
- `components/BeastDuelRitual.tsx`：揭牌／交鋒的實際播放點。
- `tests/beast-sound-profiles.test.cjs`：卡片覆蓋、素材存在、對手不發聲與退出清理。

### 驗收

逐張確認本體與叫聲是否相符；不能只因為檔案名稱不同就宣稱六十種聽感都通過。記錄素材來源與加工結果，區分真實動物錄音、人工擬音及神獸設計音。素材缺失或授權不明時不以其他不相關動物頂替。

以不扣收藏的預覽驗證：玩家揭牌有自己的聲音、對手揭牌與出手不混入叫聲；一比一保留手動決勝揭牌，二比零自動演完第三組。確認退出停止音訊，音訊失敗不阻擋比分。最後執行相關測試、建置與健康檢查。

### 實作進度

正在建立授權素材庫並接線。完整配音與實測完成前，不宣稱六十張已全部配音或已完成聽感驗收。

### 3. 已驗證的正確生成方法

#### 3.1 核心原則

每一張成品都必須以指定季節底板作為「編修目標」。季節由該神獸的新規格指定；沒有指定時，先確認後再生成。

不要用文字重新生成一整張卡牌，也不要只把神獸獨立圖硬疊到底板上。前者會讓卡框與背景飄移；後者可能出現假的透明棋盤格或不自然的光影。

正確方法是：

```text
固定季節底板 + 以底板做精準編修 + 在中央留白加入一隻神獸 = 最終卡圖
```

#### 3.2 每張卡的操作流程

1. 選擇指定季節的工作母版，先確認該底板為唯一視覺來源。
2. 將底板作為圖片編修的輸入圖，而不是只當文字風格參考。
3. 在提示詞中明確描述該神獸的物種、體態、氣質、四象部位本源與專屬能量。
4. 明確要求神獸只填入中央留白：頭部在上半部、主體落在中央、下半身自然融入既有雲海。
5. 用「不得改動」條款鎖住卡框、四角飾紋、星盤、雷電／天象、雲海與外側黑邊。
6. 檢查成品後，以新版檔名存入 `public/star-beasts/`；底板永遠不覆寫。

#### 3.3 已驗證結論

**底板編修生成**比「完整卡牌重新生成」或「透明神獸硬合成」更穩定。新系列一律使用本章流程，並以春夏秋冬母版為準。

### 5. 提示詞撰寫規則

- 必須先說清楚「牠是什麼動物」，再說四象部位如何化生到牠身上。
- 必須寫出與同組神獸不同的輪廓，不能只替換名稱與顏色。
- 不要只寫「霸氣」或「神聖」；改為可畫出的描述，例如「寬肩厚頸、正面俯視、厚重胸甲」。
- 每張只設一個最亮焦點，例如亢金龍的咽喉王令星印。
- 色彩、雲霧與能量效果需服從指定季節底板，不能蓋過底板的主色與景物。
- 每次只生成一張；確認物種、姿勢與位階正確後才繼續下一張。

### 6. 完成前檢查

- 是否使用了指定季節的工作母版。
- 金色卡框、四角、天象裝飾與既有季節景物是否仍完整。
- 神獸是否一眼可辨識為指定物種。
- 該神獸是否和同組已完成者有清楚的輪廓與位階差異。
- 主體是否置於中央，且沒有遮住主要卡框。
- 最亮焦點是否符合該神獸的新規格。
- 是否沒有文字、亂碼、Logo、浮水印、UI 或多餘生物。
- 是否輸出為 PNG，並可安全縮放為 `275 x 480 px`。

## 十三、成年本命神獸卡生成規格

> 原本獨立在 `docs/28-star-beasts-adult-natal-beast-production-spec.md`，已整併進本檔。原文保留。

### 範圍與流程

本規格適用二十八宿的成年「本命神獸」卡。成年神獸為客戶的預設第一視圖；「神獸幼子」是同血統的深入查看內容，不能以同一隻神獸長大的敘事取代成年本體。

- 生產採計畫性逐張優化與逐張接入：一次只處理一張，依四季分段完成並回報；使用者已授權在完成第 1 張標準驗證後，持續執行至第 28 張，最後再進行全套驗收。不得同時批量生成或用未驗收的失敗稿批量接入。
- 候選一律採版本化新檔，未確認前不得改 `data/star-beasts.json` 的正式引用；既有資產永遠保留作為回復點。
- 確認接入時，只改已批准卡片的成年 `image`；其 `youngDivineImage`、其餘二十七張、運算與 UI 均不可連帶變更。

### 不可變的系列結構

1. 四季／四象歸屬固定：春＝東方蒼龍、夏＝南方朱雀、秋＝西方白虎、冬＝北方玄武；不得跨季或跨象。
2. 每張都有完整金色星宿細絲卡框、上下對應四季／四象徽記、950×1656 網站 PNG，以及至少 1900×3312 的高解析母檔。
3. 每張背景依自身星宿名稱、神獸物種習性、元素與棲地單獨生成；不得以同一山水模板套用所有卡。
4. 場景必有一致的前景、中景、遠景、景深與遮擋關係，但背景不可搶過成年神獸本體。

### 成年本命神獸

1. 主體第一眼須呈現成年力量、重量、守護與蓄勢戰鬥感；頭、眼、命名武器、腳爪與身體比例必須清楚且解剖合理。
2. 成年本體須與同組幼子共享物種、元素、圖騰、材質與守護領域的血統語彙，但兩者是親代與幼子，非同一隻的生長前後。
3. 不得幼態、卡通化、薄弱、普通動物化、貼圖化或以特效遮住實體輪廓。

### 名字就是武器

每個星宿名稱都必須提取一個專屬的「核心字義武器／能力器官」，且必須落在神獸本體可辨識特徵，而非背景或通用特效。

- 武器必須在第一眼清楚可辨：完整輪廓、銳利材質、合理比例，與背景具足夠明暗或冷暖對比。
- 神性光芒只用來強調武器，不得吞掉其形體、細節或材質；不得被霧、景深、鬃毛、背景、粒子或過曝遮住。
- 各卡武器不得複製。後續二十七張必須逐張解析自己的名稱、物種與能力，選擇不同的本體武器／器官。
- 範例：角木蛟的命名武器是「角」，不是腳爪。龍角的角脊、角尖、材質與克制淡金白神性微光必須清楚，並與青玉本體形成層次；「木」由春木生發與青綠能量表現；「蛟」由江河、雲水與濕潤水系鱗光表現。腳爪是戰鬥支撐，非命名焦點。

### 材質與空間真實性

1. 水、石、毛、鱗、羽、角等材質必須一眼可分。水只能以自然流向、折射、反射、水花與接觸陰影表現；石頭是自然侵蝕河石／山石；鱗、羽、毛與角只能留在本體相應輪廓內。
2. 禁止網格、菱形、龜甲、鱗片外溢、重複貼圖、亮粉、裝飾性刻紋、規則線網、AI 拼貼感與物種紋理誤用。
3. 光源、透視、焦距、色溫、邊緣銳度、材質密度、遮擋、接觸陰影與景深必須一致；任何頭像貼上、漂浮邊緣、重複石頭或局部過銳皆視為不通過。
4. 主體要以光影、體積轉折、材質高低與適度邊緣光從背景凸出；遠景可柔化，但主體與命名武器不可被霧化。

### 交付與驗收

每張候選須先在獨立檔案中視覺驗收：四季／四象、名稱武器、成年比例、背景棲地、材質分離、空間一致性、金框徽記與尺寸。使用者明確批准後，才可更新該張成年 `image`、執行正式 build、TypeScript、HTTP 與成年／幼子切換驗證；不提交、不推送，除非使用者另行要求。

## 十四、星宿幼體生產規格

> 原本獨立在 `docs/28-star-beasts-young-divine-beast-production-spec.md`，已整併進本檔。原文保留。

### 1. 系統定義

卡牌進化關係固定為：

```text
星宿幼體（新卡） → 星宿覺醒體（現有 28 張正式卡）
```

星宿幼體不是普通動物，也不是褪色或低品質版本。牠從出生就是指定神獸：必須保留覺醒體的物種、主色、專屬材質、流光、星印與四象部位來源。差異只在於幼體的角、羽翼、尾巴、甲片、星核與能量仍未完全長成。

### 2. 全卡共通視覺規則

#### 必須保留

- **同一個神獸身份**：幼體必須能一眼對應現有覺醒卡，不能只像普通幼獸。
- **核心色與材質**：保留覺醒體主色、鱗片／羽毛／毛皮材質及古金細工語言。
- **本命星核**：每隻都有一個小而明確的發光星核；不是完全移除能量。
- **未完成特徵**：每張必須明確呈現「尚未長成」的器官或裝備，例如角芽、稚齒、短鬃、未展開羽翼、少量幼甲；不可把覺醒體完整特徵縮小照搬。
- **神裝限制**：幼體只可保留一個核心裝備（小胸甲、肩甲、護符或少量初生甲片），其他部位回歸原生毛皮、鱗片或羽毛。
- **流光特效**：保留約 20–35% 的神獸流光語言，只能圍繞星核與局部器官；不能形成覺醒體的大型爆發或鋪滿全身。
- **幼體比例**：頭部、眼睛與腳掌相對較大；四肢較短、身軀較圓或較小。姿態可帶好奇、警覺、倔強或學習感；可愛來自發育比例，不來自寵物配件。

#### 共用構圖與色彩鎖定

- **面向與辨識性**：神獸不可背對觀者，必須清楚看見臉部、眼神與至少部分胸肩／身體特徵，讓物種、星核與幼體神性可以一眼辨識。正面朝前是可用的強構圖，但不是唯一解；自然的微正面、三分之二側面也可，前提是臉部仍清晰可見。
- **主體位置**：除非個別規格另有要求，幼體自然置於卡面中央或微偏下半部，保留環境敘事與卡框呼吸空間；不可貼邊、被邊景擠壓，亦不可為了對稱而做成僵硬置中。
- **明度與色彩**：成圖必須明亮、清楚且有前中後景層次；使用各季既定主色作為可辨識的亮色焦點。禁止把整張卡壓成渾濁的深棕、黑褐、髒灰或低對比暗色，神獸臉部、星核與主色材質必須可讀。

#### 能量成熟度

| 元素 | 星宿幼體 | 星宿覺醒體（現有） |
|---|---|---|
| 體態 | 幼態、未長成的神獸構造 | 成熟、威嚴、完整位階 |
| 星核 | 一個小型聚光點 | 完整星圖、強焦點或星陣 |
| 符紋 | 斷續、局部、剛萌發 | 全身展開、完整可讀 |
| 流光 | 星核附近的微光、少量短流光 | 擴散至環境的神性異象 |
| 特徵 | 角芽、稚齒、幼羽、少量幼甲、短尾尖 | 完整冠角、翼展、甲片、長尾與天象 |

#### 絕對禁止

- 做成一般家養寵物、寫實動物照片、可愛玩具或幼兒插畫。
- 刪除所有神性特徵後只留下普通動物。
- 把成獸的完整角、鎧甲、羽翼、鬃毛或星陣直接等比例縮小。
- 改變物種：幼蛟不是蛇、心月狐不是狗、參水猿不是猴子、畢月烏不是猛禽。
- 成人形、武器、文字、Logo、UI、浮水印、重複頭部、額外肢體。

### 3. 生成輸入與輸出規則

每張生成時固定使用兩張輸入：

1. **編修目標**：該季的 v2 人間邊境底板，用以鎖住卡框、場景與構圖。
2. **神獸參考**：同編號現有的覺醒卡，用以繼承同一神獸的色彩、物種特徵、星印與材質；不得複製覺醒卡的背景、姿勢或完整能量規模。

底板：春 `spring-base-v2-master-950x1656.png`、夏 `summer-base-v2-master-950x1656.png`、秋 `autumn-base-v2-master-950x1656.png`、冬 `winter-base-v2-master-950x1656.png`。

輸出：`public/star-beasts/{season}/{id}-{slug}-young-divine.png`，尺寸 `950 × 1656 PNG`。現有覺醒卡完成後改名為 `{id}-{slug}-awakened.png`，但此階段不改檔。

### 4. 通用提示詞骨架

```text

輸入圖片 1：唯一且鎖定的 {季節} 人間邊境卡牌底板；僅作精準編修目標。

避免：普通寵物、錯誤物種、無神性特徵、背對觀者、成年人形、文字、Logo、浮水印、UI、重複頭部、多餘肢體、遮住卡框。
```

### 5. 東方蒼龍｜春季星宿幼體（01–07）

背景：林間石橋、翠綠丘陵、竹林、淺溪與粉櫻。所有幼體保持春季青綠、玉色與淡金流光。

#### 01 角木蛟｜幼蛟｜蒼龍之角

- **神獸幼體外型**：青玉鱗片、細長幼龍身、短四肢、未成熟的龍鬚；額頭已有一支短小玉角，不可像普通蛇。
- **流光與星核**：短角內有淡金木靈流光；背脊幾片鱗片帶嫩綠星點。
- **姿態**：盤在石橋旁岩石，半抬首，尾端繞過苔蘚。
- **覺醒連結**：短角與背脊星點長成蒼龍之角、完整木紋與龍脈。
- **硬鎖**：無翅膀、不可成年巨龍、不可只畫成蛇。

#### 02 亢金龍｜幼金龍｜蒼龍咽喉

- **神獸幼體外型**：深墨青鱗、較厚短的龍身、端正長頸、短角與小鬃棘；和角木蛟的細長蛇形輪廓明確不同。
- **流光與星核**：咽喉中央一枚小型古金鱗是唯一亮點，金色細流沿頸鱗短暫滑動。
- **姿態**：伏於溪邊扁石，頭部略高、像守禮的幼龍。
- **覺醒連結**：金鱗成長為正直威權的咽喉王令星印。
- **硬鎖**：無王冠、王座、巨大金環或成年龍威壓。

#### 03 氐土貉｜岩紋幼貉｜蒼龍胸肋

- **神獸幼體外型**：土褐與青灰交疊的厚毛、貉的短耳與蓬尾；胸肋有天然礦物般的毛紋，不可做成浣熊或一般小狗。
- **流光與星核**：胸口岩紋中心一枚低亮琥珀星核，細金土氣僅貼著前胸流動。
- **姿態**：走在石橋邊草坡，前爪踩在小石上，穩重不畏縮。
- **覺醒連結**：胸肋岩紋長成承載基石的土甲與星印。
- **硬鎖**：不用一般寵物比例、沒有整副鎧甲、沒有巨石爆發。

#### 04 房日兔｜日紋幼兔｜蒼龍腹部

- **神獸幼體外型**：雪白絨毛帶淡金耳尖、眼神明亮；耳緣有極細金線，腹部毛色有柔暖日紋，不是普通白兔。
- **流光與星核**：腹側晨金星核像小太陽種子，微光沿腹毛與前爪輕流。
- **姿態**：坐在石橋旁草花間，前爪微抬，神情靈動而非寵物擺拍。
- **覺醒連結**：腹部日紋會成為明朗財祿的日華星核。
- **硬鎖**：無巨型日輪、火焰、衣物、項圈或玩偶感。

#### 05 心月狐｜月紋幼狐｜蒼龍心臟

- **神獸幼體外型**：銀灰至月白的毛皮，必須保留覺醒體的六條蓬鬆幼尾；每條尾巴較短柔軟、帶淡月銀尾尖且可清楚辨識。額心與胸口有極細月紋，眼神深而警覺。
- **流光與星核**：心口一輪小月核，月華沿胸毛與六條尾尖短暫游走。
- **姿態**：半蹲或端坐於櫻花樹根下，正面或微正面面向觀者，六尾自然環抱或錯落展開。
- **覺醒連結**：月核長成心月狐的洞察力、神秘魅力與完整月華。
- **硬鎖**：恰好六尾；非一般狐狸、非九尾、非魅惑人形。

#### 06 尾火虎｜火紋幼虎｜蒼龍之尾

- **神獸幼體外型**：金橘幼虎、自然虎紋中混有赤紅火紋；尾端有未完全點燃的小火苗狀毛流，虎瞳帶星火。
- **流光與星核**：尾端火種是星核，少量紅金流光沿尾與脊椎短距離遊走。
- **姿態**：伏在溪畔岩石上，前爪壓住落葉，蓄勢、敏捷、帶野性。
- **覺醒連結**：尾火成為爭鬥好勝與逆境爆發的完整火尾。
- **硬鎖**：不可像普通虎寶寶；不可全身起火或出現火海。

#### 07 箕水豹｜水斑幼豹｜蒼龍尾末

- **神獸幼體外型**：青灰與墨綠的豹紋幼豹，身形纖長、耳尖與尾尖帶水藍透明毛光；不可像家貓或老虎。
- **流光與星核**：肩側一枚豹斑含水藍星核，細水光沿尾末形成短短漣漪。
- **姿態**：站於淺溪踏石，前爪輕觸水面、眺望遠方山徑。
- **覺醒連結**：水斑與尾末漣漪會成為漂泊風浪與完整水行星紋。
- **硬鎖**：無巨浪、無水甲、無飛躍出框。

### 6. 北方玄武｜冬季星宿幼體（08–14）

背景：雪松村橋、半結冰溪流、遠村燈火與冷月。所有幼體維持冰藍、雪白、冷金與深夜星光。

### 9. 生產前檢核與順序

1. 每張先載入「季節幼體底板」和「同編號覺醒卡」兩張參考。
2. 先確認種族特徵、主色與星核，再生成一張。
3. 生成後核對：是否像同一隻神獸的幼體，而非一般寵物；能否一眼看見星核、流光及未成熟特徵。
4. 確認單張後才開始下一張；發現物種或神性不足時只針對一項重做。
5. 全部確認後，才寫入正式交付目錄與資料檔。

## 十五、初相／覺醒視覺規範

> 原本獨立在 `docs/28-star-beasts-evolution-spec.md`，已整併進本檔。原文保留。

### 卡牌層級

每一隻神獸有兩個固定層級：

- **初相（Base）**：星宿力量尚未完全顯現。動物本體辨識最優先，氣質安靜、靈性初醒。
- **覺醒（Awakened）**：現有的 28 張正式神獸卡。完整星紋、季節異象、古金細工與神獸位階都已顯現。

初相不可改變物種：狼仍是狼、烏鴉仍是烏鴉、參水猿仍是無尾猿。覺醒感來自星宿力量與四象部位的顯化，而非改造成另一種動物或人形角色。

### 初相卡共同規則

1. 卡框、四角飾紋、上下中央飾件與卡牌比例與覺醒卡相同。
2. 主體置於中央但尺寸較覺醒卡小約一級，姿態以停立、棲息、行走、蹲伏為主。
3. 每張只能有一個微弱的「本命徵兆」：星點、淡符印、眼眸微光、單一羽紋或小範圍靈氣。
4. 不使用滿身符紋、完整鎧甲、巨大光環、戰鬥爆發、跨框特效或過多星象。
5. 保持礦物顏料、古金細工、東方玄幻收藏卡質感；不含任何文字、Logo、浮水印或 UI。

### 四季初相底板方向
