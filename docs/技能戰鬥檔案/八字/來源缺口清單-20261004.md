> 產生方式：`node scripts/bazi-registry-completeness.cjs`（16 筆 claim，OK 11，ERROR 5）＋逐筆讀取登記表與 `evaluateClaim`。

## 閘門規則（現行，業主定死，未改）

`lib/iching-source-gate.ts` `evaluateClaim`，八字知識類（非工程類）要全部符合才算 VERIFIED：

| 條件 | 門檻 |
|---|---|
| 權威檔 `authority_files` | ≥ 1 |
| 大數據 `big_data_sources` | ≥ 1 |
| 交叉來源 `cross_references` | ≥ 3（去重後） |
| 交叉來源授權 | 每一個都 `can_cite = PASS` 且 `license_terms` 不含「待查核」 |
| 交叉來源可信度平均 | ≥ 90（A=95、B=85、C=60、D=30） |
| D 級來源 | 交叉來源中不得有 |
| 原典 | 交叉來源中 `kind` 為「原典」或「原始研究」≥ 1 |
| 版本可追溯 | 每個交叉來源 `edition` 有值且不含「待查核」 |
| 重大衝突 `conflicts` | 0 筆（>0 直接 CONFLICT） |

`scripts/bazi-registry-completeness.cjs` 另外要求：登記狀態 `status` 也是 VERIFIED（登記表不得手填；只能在閘門重算為 VERIFIED 之後依專案流程同步）、非工程類至少掛一個原典類來源。

注意：閘門目前**沒有「已解決衝突」欄位**——`conflicts` 陣列有任何一筆就判 CONFLICT。衝突即使以證據解決，要怎麼保留歷史紀錄（例如另設 `resolved_conflicts`）屬閘門設計，需業主決定；本次不改閘門、不刪衝突紀錄。
