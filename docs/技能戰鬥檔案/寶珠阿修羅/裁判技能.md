# 裁判技能（寶石捷連線：前端先演、後端判決）

2026-11-19 業主定案。歸屬寶珠阿修羅技能檔案，與[寶珠戰現行規則](寶珠戰現行規則.md)並讀；不新增第二套遊戲核心。

## 真實終局強制鎖定（2026-11-20 業主確認）

本條適用寶珠連線（寶石捷連線）雙方：玩家與阿修羅一視同仁，沒有任何一方可提前獲判勝利或失敗。任一方即使只剩 1 點有效生命值，仍須打到真實終局，不能自動判該方戰敗或另一方獲勝；明確主動認輸或跳關另依下述退出條款處理。與既有文字衝突時，僅終局判定依本條；其他玩法與技能維持既定版本。

- 對戰必須進行到後端確認的真實終局，才能宣判勝負。血量仍未耗盡、仍有依法可繼續作戰的角色時，不得判該方負或對手勝；必須保留繼續遊玩與逆轉機會。單一卡倒下不等於整隊戰敗，須核對本場完整隊伍及既有合法補位、後備與已生效效果，不以畫面暫時只剩一張卡代替判定。
- 生命耗盡依後端實際扣血、治療、護盾與既有技能結算後的權威狀態核對；前端動畫、血條顯示、預演或舊回應均不得自行宣判。雙方同時耗盡而既定規則未核定結果時，不得擅自指定勝方。
- 血量尚未耗盡時，只有玩家明確主動選擇認輸或跳關，才可依既定退出流程處理。主動認輸與跳關必須分別記錄，不得把跳關擅自定義為戰敗、對手勝利或新增扣卡／敗局處罰；未確認的退出契約不得補造。斷線、逾時、重整、離頁、暫停與請求失敗不等於主動認輸或跳關。
- 嚴禁以回合數上限、經過時間、分數差、剩餘血量高低、預測勝率、阿修羅話術或 AI 判斷代替真實終局；不得因玩家暫時落後就提前判輸，也不得因阿修羅暫時落後就提前判它輸。技術限制或失敗只能如實回報狀態，不可偽裝成勝敗結算。
- 不可繞過的判負必要條件：除明確主動認輸另依既定退出契約處理外，必須等該方本場完整隊伍的有效生命值實際耗盡，並完成既有合法補位、後備及已生效效果的終局核對，才可判該方戰敗。即使被預測為「穩輸」「必敗」「沒有翻盤可能」，或分差再懸殊，也不能提早判輸；仍有 1 點有效生命值就必須保留繼續對戰。玩家與阿修羅完全對等，不得增設任何預測必敗捷徑。跳關仍僅按既定退出流程處理，不等同戰敗。
- 勝敗顯示、後端結果、戰局保存、關卡進度與獎勵收據必須使用同一份已核對終局事實。重送不得重複結算，未達終局不得發出勝敗結果或提前消耗敗局權益。

驗收必須對調雙方，涵蓋雙方仍有血、單卡倒下但隊伍仍可戰、長回合／長時間仍可戰、真實生命耗盡、同時耗盡、明確認輸、跳關、斷線及重送；核對 API、畫面與保存結果一致。本條是強制工程規範，不代表程式已完成修復或能永久不出錯；未完成實測不得宣稱通過，也不藉此新增復活玩法。

## 棒球比喻

| 角色 | 負責 | 禁止 |
|---|---|---|
| 前端＝球員 | 玩家一放手就立刻演（高亮、消除、掉珠、補珠），把遊戲概念與美術做好 | 不判對錯、不算傷害／獎勵／掉珠數量、不補造結果 |

## 一回合怎麼走

1. 玩家放手。前端先用純運算預演這一手（`predictOrbBoard`，幾毫秒），算出預演指紋 `claim`。
2. 前端立刻把請求（帶 `claim`）送後端，**同時**開演預演畫面，不等回覆才第一次動。
3. 後端 `app/api/beast-game/orb-turn/route.ts` 用權威結果逐格比對，回 `referee` 判決：
   - `PASS`／`KEEP_ANIMATION`：演得跟後端一致，畫面維持，直接接後端結算（傷害、補血、反擊、獎勵）。
   - `FOUL`／`RESTORE_AND_REPLAY`：演得不同，前端**立即**停掉預演、恢復原盤，改播後端確認的版本。
   - `NO_CLAIM`／`PLAY_SERVER`：沒有預演（例如無效路線、其他模式），直接播後端版本。
4. 前端沒收到判決（舊版後端、錯誤回應）一律視為不通過，播後端版本——不自己認定「應該對」。

## 判決的界線（寫實）

- 判決只決定「預演動畫留不留」。數值與獎勵永遠只看後端結算，前端送來的血量、攻擊、庫存不能取代後端已簽署／保存的戰局。
- 指紋是一致性檢查，不是防作弊簽章；作弊防線是後端權威結算。FOUL 不等於客戶作弊，只代表這次演得跟後端不同，一律恢復重播，不扣客戶資料、不重複發獎。
- 實作：`lib/beast-game/match3/referee.ts`（`judgeClaim`、`withReferee`、`replayDigest`）；前端只讀 `referee.verdict`。
- 速度：後端單回合運算實測約 0.4 毫秒（中位數，40 次固定種子）。操作回饋、伺服器往返、完整演出須分開量；網路往返與冷啟動不是程式能消除的，預演是用來遮住往返時間，不是消除它。本輪未取得正式站實測（正式站目前被平台停用）。
- 法珠掉落與接取的儀式時長獨立保留，不被裁判流程縮短。

## 守門

`npm run test:beast-referee`（已併入 `test:beast-match3-replay`）：100 次 PASS、100 次 FOUL 恢復重播、100 次無預演；亂填指紋不得當 PASS；判決不改後端結算；前端不得出現自行比對（`predictionMatches`）、必須帶 `claim`、後端三條回合路徑都掛判決。

## 按寶珠卡頓的真因（2026-11-19）
- 追蹤檔顯示：按下攻擊那一刻，主執行緒同步解碼神獸關鍵幀（webp），單張約 140ms（4 倍降速）、共 6 次。
- 修法：`BeastRigStage` 載入關鍵幀後先 `decode()`，再轉成 `ImageBitmap` 給畫布使用；畫布不再依賴瀏覽器圖片快取。
- 實測（4 倍降速、開發模式）：最長單一任務 606ms → 237ms；主執行緒圖片解碼 6 次 → 1 次。
