# 計數真實性與穩定保存

本技能規範後續維護，不代表網站已通過驗收。以實際資料庫、程式與測試結果回報狀態。

## 保存與呈現順序

- 操作先產生事件識別；重試使用同一識別。事件與累計必須在同一筆資料庫交易中完成，唯一限制防止重複計數，原子更新避免並行覆蓋。
- 後端確認持久保存後才回傳成功；前端只採用確認的總數。離線佇列、sendBeacon 接受傳送、逾時都不等於已保存，不能先加數或顯示成功。
- 讀取不新增或回寫計數。不可用本機最高值覆蓋資料庫，不使用先讀後寫的加一備援。
- 讀取失敗保留最後確認值並標示等待更新；沒有確認值時呈現載入或暫時無法讀取，不把錯誤、缺設定或空回應當成零。
- 防止較舊回應覆蓋新狀態。歷史快取不等於真實來源；如需改快取版本，先保留舊值供核對，不直接混入新的已核實總數。

## 歷史與統計口徑

- 變更前備份原始檔與資料庫快照並保留校驗摘要；不把客戶識別、IP 或金鑰寫進 Git、技能或公開報告。
- 不直接歸零、刪歷史、填猜測底數，或把來源不明總數認定為真實。將已核實事件與待核實歷史分開管理，清楚說明涵蓋範圍。
- 紀錄可能裁切、去重或包含測試流量，不能單憑目前陣列長度否定全部歷史，也不能認為每個事件必定代表獨立真人。
- 同次操作重送只算一次；客戶重新造訪可算新的瀏覽次數。允許再次按讚時，標示次數而非不重複人數。
- 持久共享資料庫是正式站來源。Vercel 臨時目錄不能保證跨執行個體或部署保存；資料庫不可用時不得悄悄切換成臨時檔並宣稱成功。

## 維護位置與驗收

從 `lib/visitor-counter.ts`、三個計數 API、`lib/local-*-counter.ts`、`components/FeatureVisitorCounter.tsx`、`components/AiTrustFeedback.tsx`、`components/AiLikeFeedback.tsx` 追蹤端到端流程。檢查正式環境設定，不輸出秘密。

執行實際程式的行為測試：同一事件重送、不同事件並行、回應順序顛倒、保存成功但回應遺失、斷線重連、重新載入、跨裝置與重新部署。測試使用隔離資料或可回滾交易，不往客戶正式統計灌測試流量。

`node tests/counter-confirmation.test.cjs` 僅驗證前端確認順序，不能代替資料庫持久性及整體健康檢查。不得為了全綠而放寬真實性要求；若修正錯誤測試，補上能證明相同業務要求的行為證據。

涉及 Supabase 時使用其技能與現行官方文件。提交與發布依專案工作規則，完成、測試及上線狀態分別回報。
