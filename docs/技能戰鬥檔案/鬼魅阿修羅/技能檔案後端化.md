# 鬼魅阿修羅｜技能檔案後端化（後端運算、前端顯示、固定順序）

## 統一運作流程（2026-10-28 業主確認）

填寫資料 → 依所選功能的既定公式運算 → 核對本次結果與來源 → 後端對應阿修羅技能檔話術 → 前端顯示與引導。

- 統一的是執行契約，不是把八字、紫微、九宮格、生命密碼與卜卦改成同一套公式。各功能保留自己的來源、版本與適用條件。
- 生辰整合沿用八字 → 紫微核對 → 易經的既有三核心；獨立卜卦依指定起卦方式處理，不強制加入其他排盤。跨系統補充只允許已有明確對應依據的結果。
- 同一位客戶、本次輸入與本次結果必須對應；改資料、換人、離頁後，舊請求不得更新結果、錯誤或忙碌狀態。三張時間卡與主結果共用同一份後端回傳。
- 缺資料或核對失敗須明確標示；依賴失敗資料的話術不得輸出。不得代填未知生辰、補造結論或以舊結果假裝本次成功。
- 公信力來自可追溯的書名、卷章、原文、技能檔條目及適用取法。來源有分歧就保留狀態；古籍記載不等於政府認證，也不保證個人預測正確。
- 阿修羅只轉譯有依據的本次結果；口氣可以有力，結論不得超過依據。前端不排盤、不挑句、不生成內容。

## 資料流

```
lib/ghost-asura-skill-content.ts   原樣照錄的文字資料（唯一內容來源）
lib/asura-display-alias.ts         技能名相 ASURA_SKILLS、四時語彙、顯示前換字
          ↓
lib/ghost-asura-skill-file.ts      buildAsuraSkillFile()：後端組成固定順序、可序列化的資料
          ↓                         ↘
app/ghost-asura/skill/page.tsx      GET /api/ghost-asura/skill-file（同一份資料）
app/ghost-asura/skill/AsuraSkillBlocks.tsx   前端只照印
```

## 固定順序（只在 `SECTION_ORDER` 定義）

壹 印記已開（mark）→ 貳 最高鐵律（law）→ 參 三張功能卡（cards）→ 肆 話術核心（voice）→ 伍 三層話術結構（layers）→ 陸 數量鐵律（count）→ 柒 前端用語對照與柱位（terms）→ 捌 固定名稱表（names）→ 玖 四層解盤（reading）→ 拾 視覺規則（visual）→ 拾壹 三大承諾（promise）→ 拾貳 修改範圍與驗收清單（scope）→ **拾參 技能清單（skills）**

- 新區塊只能加在最後；前十二區的順序不得更動。
- 技能清單分兩組：**名相技能**（`ASURA_SKILLS`，千歲壽→障月→障日→一剎那→四有→業果→業鏡→生緣→落位）＋**融會技能**（`ASURA_FUSION_SKILLS`，目前是九宮融會）。順序＝[技能清單.md](技能清單.md) 的列順序。
- 每個區塊有編號（`order`，從 1 連續）與固定 id；每個顯示單位（block）有固定型別。

## 鐵律

1. **內容只由後端給**：頁面與顯示層程式碼不得內建任何中文內容、不得直接匯入內容檔。
2. **前端不排序、不篩選、不反轉、不運算**：後端給什麼順序就印什麼順序。
3. **顯示前換字在後端做**（術數用語不上畫面，`asuraDeepScrub`），前端不處理。
4. **只有一份內容來源**：`lib/ghost-asura-skill-content.ts`；舊位置 `app/ghost-asura/skill/content.ts` 不得再出現。
5. 新增顯示單位型別時，後端型別、顯示層 `case`、測試要一起補（測試會擋「後端送出但顯示層不認得」）。
6. 阿修羅口吻的短句經 `lintAsuraVoice`；不得含術數用語。
7. 兩個互動元件（過去／現在／未來時間軸卡、生辰解盤）仍由它們自己的後端 `/api/ghost-asura/reading` 取資料，只是放在 `liveReading` 顯示單位裡。
