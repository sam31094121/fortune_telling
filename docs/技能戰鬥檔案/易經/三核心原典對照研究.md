## 已定位的程式落差

1. `lib/iching-engine.ts` 的 `castHexagramFromBirth` 以西元年加公曆月日取數，結果標為「梅花易數」。卷一「年月日時起例」年取十二地支序數，月以正月起算，日以初一起算。因此現有西元取數不能直接聲稱符合該傳本。這是實際算法差異，不只是介面文案。
2. `castHexagramCertified` 只檢查流程憑證後呼叫上述函式。因此「三核心流程通過」不等於「傳統算法已核實」。健康檢查需要獨立的原典算例。
3. 八字兩種舊老師使用 `castHexagram`，此函式以文字雜湊映射卦象。不能當成已核對生辰卦。來源閘目前阻擋這些老師，不代表算法缺口已修復。
4. 關係故事提示詞要求模型推算星曜，後備故事有固定卦象。Google 目前停用使該生成不可用，但重啟前仍須移除這些未核對路徑。

## 分批修復與驗收

已另存 `梅花年月日時原典算例.json`：觀梅占、牡丹占的输入及原文預期卦象。預期值取自傳本占例，不由本站引擎產生。這是後續算法回歸素材，尚未宣稱正式引擎通過。

1. 曆法：以官方資料建立獨立日期樣本，覆蓋農曆新年、閏月、交節、子時；記錄時區和日期精度。
2. 八字：逐條整理天乙、文昌、桃花、驛馬、華蓋的年／日干支錨點、適用柱與版本分歧。先修已能逐條證明的規則，喜用等爭議不可用多數網站投票解決。
3. 紫微：固定傳本及所採流派，安命身、五行局、十四主星、四化與閏月處理分項對照；與八字共用資料，保留各自年界。
4. 易經：將周易筮法、梅花取數與本站象徵映射分清。以卷一觀梅占的年支、月日、時數手算作獨立算例，再決定生辰用途、年界與閏月政策。不得直接將出生時間冒稱原典占問時間。
5. 程式修改後才做端到端驗收。刻意注入錯日期、錯時柱、缺來源、舊快取、偽成功，確認解讀與健康狀態同時拒絕。

完成標準是每條規則都有版本定位、輸入定義、分歧記錄、獨立預期值和實際測試結果；不能靠同一引擎比較自己證明正確，也不能靠補足三個轉載網址放行。
