# 三核心功能清點

2026-09-26 第一輪，依 app/ 與 lib/ 內實際起卦及三核心呼叫檢索。這是靜態路徑稽核，不代表所有線上入口已操作驗收。

## 正式規則缺陷

| 功能／檔案 | 實際路徑 | 判定與待修 |
| --- | --- | --- |
| `lib/iching-engine.ts` | 生辰年月日加總；帶憑證仍呼叫同一算法 | 禁止作為已核實梅花取數；仍有呼叫，未全數停用 |
| `lib/three-core-engine.ts` | 帶憑證起卦 | 已加起卦前資料核對，但下層算法缺陷仍在；流程綠燈不是正統認證 |
| `lib/insight-engine.ts` | 先跑三核心，後又直接起生辰卦，另呼叫共感包裝 | 有重算路徑，須改為傳遞同一次已驗證 reading |
| `app/api/insight-analyze/route.ts` | 產生 analysis 後再次跑三核心、組客戶解讀 | 重複計算需收斂；此輪尚未驗證所有分支輸出阻擋 |
| `lib/iching-psychology.ts` | buildEmpathicReading 直接依生日重起卦 | 應接收已核對卦象；本身不是另一種正統起卦法 |
| `app/api/nameology-analyze/route.ts` | 通過時用三核心 reading；另留生辰重算及未知時辰文字象徵分支 | 有旁路需收斂；未知時辰象徵不能當正式生辰卦放行 |
| `lib/red-luan-iching-reading.ts`、`app/api/red-luan-heartbeat/route.ts` | 以出生日期再次起卦 | 保留時辰檢查仍不足，應接三核心結果並核對紅鸞獨立規則 |
| `lib/zodiac-engine.ts` | 有時間便直接起生辰卦 | 此分支沒有三核心完整檢查，且依賴待修算法；不代表整套西洋星座算法已判錯 |
| 八字 google-reading、horror-reading API | 姓名、日主、格局文字雜湊起卦 | 來源閘目前阻擋；不得只調來源狀態就恢復 |
| `lib/ziwei-teacher/teachers.ts` | 宮名、主星、流年文字雜湊另起卦 | **新增缺口**：入口已核對三核心，老師仍自行另起卦；紫微排盤正常不代表其易經解讀已核實 |
| `lib/growth-center-engine.ts` | 週次、個人種子、主題文字雜湊 | 只能視為產品映射候選，無原典依據不得以正式起卦呈現 |
| `app/api/solar-term/route.ts` | 節氣名稱與年份文字雜湊 | 節氣曆法與附加卦象須分開驗證，曆法有來源不替附加卦象背書 |
| `app/api/karma-story-generate/route.ts` | AI 推星曜、固定卦象後備 | 供應商停用中；正式用途禁止，不能隨供應商重開自動恢復 |

## 已有防線及其界線

- 紫微老師兩個 API：已在快取與生成前檢查三核心完整內容；不能因此替老師內部雜湊卦背書。
- 配對 API：AI 增強須雙方完整三核心通過和八字來源閘放行；神煞與紅鸞已分開來源判定。
- 三合一：失敗、四柱差異、時辰未知不可當完整成功；最終斷言重新核對內容和步驟。
- 健康檢查：新增原典缺陷清單檢查，未解除條目一律失敗；已停用不等於已修復。

## 原典工作與修復先後

1. 先固定曆法與三核心輸入契約，用官方曆法做外部基準。
2. 修正梅花取數及取數用途，使用獨立原典算例；不可只改名稱。
3. 刪除解讀層另起卦旁路，改傳同一次正式結果；保持有效基礎命盤可查。
4. 神煞、喜用、紅鸞各自完成版本對照，不能合併放行。
5. 原典算例、負向測試、手機操作、功能可用性全過才解除列管。
