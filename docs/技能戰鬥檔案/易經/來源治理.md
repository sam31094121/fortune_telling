# 《易經》來源治理｜交叉比對・權威檔案・大數據來源

> 業主定案（2026-09-15）：**凡有「易經」兩個字，都要有交叉比對的來源、權威性的檔案、大數據的來源。**
> 易經洋蔥心理學的權威性大數據來源，也列入本檔。
> 口令「易經」＝打開 `docs/技能戰鬥檔案/易經/`（本檔、`來源登記.json`、`易經.json`、`新人檔案.md`）。

重點不是「抓越多資料越聰明」，而是**來源夠權威、授權清楚、能交叉驗證，才准進《易經》核心**。

---

## 一、工程順序

```
八字真實排盤 → 紫微真實排盤 → 洋蔥核對 → 三合一 PASSED
→ 易經來源閘門 → 多來源交叉 → 授權檢查 → 一致性評分 → 才進《易經》核心
```

來源不能污染核心：

```
RAW_SOURCE → LICENSE_CHECK → AUTHORITY_CHECK → VERSION_CHECK
→ CROSS_REFERENCE → CONSENSUS_SCORE → HUMAN/ENGINE_RULE → CORE_KNOWLEDGE
```

## 二、來源閘門：信任等級

| 等級 | 來源 | 用法 |
|---|---|---|
| A | 古籍原典／可靠底本（《周易》《易傳》《周易正義》《周易本義》等可追溯版本） | 原典依據，優先 |
| A | 國際研究型圖書館／大型書目系統（例：哈佛燕京圖書館、WorldCat） | 核對版本、年代、書目、典藏存在性 |
| B | 大學出版社、正式學術研究（例：Columbia UP 王弼《周易》譯注、Oxford UP《Teaching the I Ching》） | 詮釋層、歷史研究層；**不可反過來取代原典** |
| C | 公開數位文本／二級整理 | 輔助查找、比字、比版本；**不能單獨決定核心規則** |
| D 以下 | 論壇、部落格、短影音、自媒體、無出處資料 | 只能進候選區，**禁止直接餵進核心** |

易經洋蔥心理學對應：同儕審查的原始研究＝「原典」；權威辭典（APA Dictionary of Psychology）＝權威檔；文獻索引（APA PsycInfo、PubMed）＝大數據來源；學術專書＝B 級詮釋層。

## 三、SOURCE_PERMISSION_GATE（每一筆來源必填）

| 欄位 | 登記表鍵名 |
|---|---|
| source_id | `source_id` |
| 作者／機構 | `author` |
| 原始網址或出版資訊 | `locator` |
| 資料類型 | `data_type` |
| 原典／註疏／研究／二手資料 | `kind` |
| 是否可引用 | `can_cite` |
| 是否可重製 | `can_reproduce` |
| 是否可大量擷取 | `bulk_extraction` |
| 是否允許自動化抓取 | `automated_crawl` |
| 是否可納入訓練資料 | `training_use` |
| 授權條款 | `license_terms` |
| 存取日期 | `accessed_at` |
| 版本／底本 | `edition` |
| 信任等級 A/B/C/D | `trust` |

權限欄只能填 `PASS`／`FAIL`／`待查核`。**沒有人工確認過的外部條款一律「待查核」，不得代填 PASS。**

**公開網站不等於可以大量抓資料。** 例如 Chinese Text Project：據業主提供的整理，該站列有自動下載限制——本專案尚未人工確認條款，所以登記為「待查核」，只可人工查證、比對、引用，不做大量自動擷取。

## 四、交叉驗證與衝突

同一個判定至少要：

```
1 個原典來源 ＋ 1 個可靠古籍版本／注疏 ＋ 1 個國際學術或研究型圖書館來源
```

- 三邊一致 → `VERIFIED`
- 有來源不一致 → `CONFLICT`。系統不能自己亂選，要留下：衝突版本、差異文字、版本年代、來源權重、採用理由（登記表 `conflicts`）。

## 五、通過標準（定死）

| 項目 | 標準 |
|---|---|
| 授權狀態 | PASS |
| 來源可信度 | ≥ 90（A=95、B=85、C=60、D=30，取交叉來源平均） |
| 交叉來源數 | ≥ 3 |
| 原典來源 | ≥ 1（心理學為原始研究） |
| 版本可追溯 | PASS |
| 重大衝突 | 0 |

任何一項沒過，不能學進《易經》核心，只能放進**「待驗證資料池」**（`PENDING_POOL`）。

神獸卡對手智能是工程判斷，不是古籍知識，改用工程證據標準：權威檔 ≥ 1、大數據來源 ≥ 1（且至少一份進版控、換機器查得到）、交叉證據 ≥ 3、全部授權 PASS、重大衝突 0。

## 七、守門與維護

- 閘門程式：`lib/iching-source-gate.ts`（純函式；狀態只由它算）
- 登記表：`docs/技能戰鬥檔案/易經/來源登記.json`
- 守門：`npm run test:iching-sources`（在推送閘內）
  - 名稱含 iching／易經 的檔案沒登記就擋
  - 來源欄位缺一就擋
  - 登記的狀態不等於程式算出的狀態就擋（不得手填 VERIFIED）
  - 引用的專案檔案不存在就擋（只在本機的大數據要標 `local_only`）
- 新增任何「易經」內容：先登記來源 → 跑閘門 → 通過才進核心；沒通過放待驗證資料池。
- 外部事實（館藏規模、網站條款、書目卷期）未經人工查證，一律寫「待查核」，不寫成事實。
