# 米其林審查手冊（永久技能・隨時調用）

> 2026-09-03 定稿。喊「**米其林審查**」或「**三大核心審查**」即開啟本檔案，
> 依 審查 → 回報 → 檢討 → 修正 → 複驗 五步執行，缺一不可。

---

## 〇、精神

米其林密探的原則：**匿名、自費、以客戶身分實地體驗、不接受招待、只憑親眼所見評分。**

翻成本專案的規矩：

1. **不看程式碼下結論，要真的點進去用一遍。** 從首頁開始，不是直接跳到目標頁。
2. **沒親眼驗證過的東西不准算分，也不准上線。** 「應該會動」等於「沒動」。
3. **扣分要指到具體位置**：哪一行、哪一個檔案、客戶在第幾屏看到。
4. **好也要說，壞更要說。** 報喜不報憂等於沒審查。

---

## 一、三大核心（審查的唯一準則）

### 核心一：品質 — 送到客戶眼前的每一個字，都必須是後端算出來的

**鐵律：前端禁止產生任何「看起來像結論」的文字。**

| 允許前端寫死 | 禁止前端寫死 |
|---|---|
| 按鈕文字、欄位標籤、區塊標題 | 月份、日期、天數、生肖、方位、職業、卦名、格局名 |
| 儀式語、載入提示 | 任何「你會…」「你是…」「你的…」句型 |
| 免責與說明 | 任何看起來像運算結果的描述 |

**查核方式**
- 前端每一段結論文字，都要能指回 API 回應的某個欄位。
- 指不回去的，就是假的，必須移到後端或刪除。
- 後端每一條結論都要帶 `ruleId` / `ruleVersion` / `source`，可回查。
- 決定性：同一輸入永遠同一輸出，測試要鎖住。

**扣分項**
- 前端自己編一句像結論的話：**直接扣 2 分**，並列為必修。
- 資料不足卻假裝算得出來（例如未知時辰仍用預設值充數）：**直接扣 3 分**。
- 同一份資料在畫面兩處講出不同答案：**直接扣 3 分**（信任崩塌）。

### 核心二：服務 — 免費，但要比付費更有尊榮感

**心法：尊榮不是華麗，是「被好好對待」。**

| 該有的 | 反面教材 |
|---|---|
| 先給價值，再要資訊 | 填完三題才給結果 |
| 缺資料就給算得出來的部分，並誠實標示未解鎖 | 資料不齊就整個擋掉 |
| 客戶最想問的放第一屏 | 免責與進度條擋在答案前面 |
| 其餘折疊但露一句誘餌 | 一次攤開三千字 |
| 讀完有下一步 | 免責＋返回首頁 |
| 回訪被認出，不必重填 | 每次都從頭來 |
| 說人話 | 品質門控、TW_SHENSHA_BASIC_V1 |

**扣分項**
- 免責出現在價值之前：**扣 1 分**。
- 客戶被擋住卻沒有替代路徑：**扣 2 分**。
- 前端出現後端術語：**每處扣 0.5 分**。
- 結尾沒有下一步：**扣 1.5 分**。

### 核心三：穩定 — 任何情況都不能把客戶丟在半路

**查核清單（每次審查都要跑）**

- [ ] `npx tsc --noEmit` 零錯誤
- [ ] `npx eslint .` 零 error
- [ ] 全部測試通過
- [ ] 手機 375px 無橫向溢出
- [ ] **開新分頁冷載入**零 console error（舊分頁的 HMR 殘留不算）
- [ ] 缺欄位、API 失敗、壞 JSON 都有中文訊息，不洩漏後端細節
- [ ] 邊界值：不知道時辰、跨年、窗口正中間、沒有任何命中
- [ ] 分享、下載這類「離開網站才生效」的產出，要真的打開來看

**扣分項**
- console 有 error：**扣 1 分**。
- 建了但沒打開驗過的產出（分享文字、行事曆檔、預覽圖）：**扣 1.5 分**。
- 進度或計數的分母寫死，客戶永遠完不成：**扣 1 分**。

## 二、五步流程（順序不可亂）

1. **審查** — 以客戶身分從首頁走完整流程；每一屏記錄「看到什麼、幾個字、想不想往下」。折疊全部打開。量時間。
2. **回報** — 給星等與分數，列出「值得給星的」與「扣分的」，扣分要標嚴重度並指到具體位置。
3. **檢討** — 對每個扣分項問：這是文案問題、邏輯問題，還是架構問題？誰造成的（既有 bug／本次改動引入）？
4. **修正** — 依投報率排序修。**修完必須複驗**，不能只看程式碼就宣稱修好。
5. **複驗** — 重跑核心三的完整清單，並重走一次客戶流程確認沒有新破口。

## 三、評分尺（★ 五星制，同時給 10 分制）

| 分數 | 意義 |
|---|---|
| 9.5–10 ★★★★★ | 值得專程前往。免費卻讓人覺得欠了人情。 |
| 8.5–9.4 ★★★★☆ | 值得繞路。會主動推薦給朋友。 |
| 7.0–8.4 ★★★☆☆ | 值得一試。會用完，但不會再回來。 |
| 5.0–6.9 ★★☆☆☆ | 有硬傷。看得出用心，但被明顯問題拖住。 |
| < 5.0 ★☆☆☆☆ | 不該上線。 |

**加分（每項 +0.5，上限 +1.5）**
- 給了可執行的下一步，而不只是結論
- 承認做不到的事，而不是含糊帶過
- 有回訪或傳播的實際載體，且驗證過

## 四、常見盲點（歷史踩過的坑，優先檢查）

1. **兩處資料源說不同答案** — 改了主要路徑卻漏掉次要引用（首屏改了、老師沒改）。
2. **建了沒驗** — 分享文字忘記帶連結、行事曆是整月橫幅。**離開網站才生效的東西一定要打開看。**
3. **平鋪等於沒說** — 四個可能性全部並列，客戶問「所以到底哪一個」。要收斂到主導項，其餘標為次要。
4. **為次要功能擋住主要功能** — 為了折疊裡看不見的紫微，把不知道時辰的人全擋掉。
5. **共用元件的 handler 沒被觸發** — 頁面自訂送出按鈕，繞過表單原本的儲存邏輯。
6. **分母寫死** — 條件渲染的區塊數量會變，計數器要算實際渲染數。
7. **儀式重播** — 第一次是價值，第三次是阻礙。
