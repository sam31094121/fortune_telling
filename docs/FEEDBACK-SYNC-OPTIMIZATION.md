# 🚀 全球實時同步優化指南

## 📋 完整流程

### 標準同步流程（用戶 A 點擊「我認同」）

```
時間軸                事件                        受影響設備
────────────────────────────────────────────────────────
T+0ms      🖱️ 用戶 A 點擊按鈕              【用戶 A 的手機】
           ↓
T+1ms      🎨 前端立即樂觀更新              【用戶 A 的手機】
           顯示 714 → 715
           ↓
T+5ms      📤 異步發送 POST /api/feedback/submit
           ├─ type: "like"
           ├─ deviceId: "device_xxx"
           └─ sessionId: "session_xxx"
           ↓
T+50ms     ✅ 後端接收請求                 【伺服器】
           檢查防重複 → 通過
           ↓

           714 → 715
           ↓
T+70ms     📡 後端廣播到所有 WebSocket      【伺服器】
           ├─ 用戶 A 的其他設備
           ├─ 用戶 B 的電腦
           ├─ 用戶 C 的平板
           └─ 用戶 D 的筆電
           ↓
T+100ms    🌍 所有設備接收推送              【全部設備】
           同時更新到 715
           ↓
T+120ms    ✓ 全球同步完成
```

## 🎯 核心特性

### ✅ 前端立即加一

```tsx
// 用戶點擊時立即顯示 +1
setCounter(prev => ({
  ...prev,
  like: prev.like + 1,  // 714 → 715 【立即】
}));
```

**用戶體驗：** 無延遲，按下立即看到變化

---

### ✅ 後端運算與存儲

```ts
// 後端 POST /api/feedback/submit
const newCount = incrementCounter(cardId, 'like');  // 715
await broadcastUpdate(cardId, 'like', newCount);   // 廣播
```

**資料保證：** 後端存儲為準，不怕前端出錯

---

### ✅ WebSocket 全球推送

```ts
// 廣播給所有連接的客戶端
function broadcastUpdate(data) {
  clients.forEach((client) => {
    if (client.readyState === WebSocket.OPEN) {
      client.send(JSON.stringify(data));
    }
  });
}
```

**同步範圍：** 所有看到這張卡片的用戶（任何設備）

## 📊 數據流向

### 前端邏輯

```
用戶點擊
  ↓
【立即】樂觀更新 UI (714 → 715)
  ↓
【異步】發送到後端
  ├─ 後端成功 → 保持 715
  └─ 後端失敗 → 回滾回 714
```

### 後端邏輯

```
接收投票請求
  ↓
檢查防重複
  ├─ 已投票 → 返回 409
  └─ 未投票 → 繼續
  ↓
計數 +1 並存儲
  ↓
廣播給所有連接
  ↓
返回新計數給前端
```

### 全球同步

```
後端廣播
  ↓
所有客戶端 WebSocket 接收
  ├─ 用戶 A 的手機 → 更新 715
  ├─ 用戶 B 的電腦 → 更新 715
  ├─ 用戶 C 的平板 → 更新 715
  └─ 用戶 D 的筆電 → 更新 715
  ↓
全球用戶同時看到 715
```

## 🛡️ 防重複投票

### 前端防重複

```tsx
// 檢查是否已投票（同一會話）
if (hasUserVoted('like')) {
  setError('您已經認同過了');
  return;  // 不發送到後端
}
```

**位置：** sessionStorage（同一瀏覽器會話）

### 後端防重複

```ts
// 再檢查一次（以防前端被繞過）
if (hasDeviceVoted(cardId, deviceId)) {
  return { error: '已投票', status: 409 };
}
```

**位置：** 記憶體（防止同一設備重複）

## 📱 跨設備同步原理

### 場景：用戶 A 有三台設備

```
【iPhone】        【MacBook】      【iPad】
   ↓                  ↓               ↓
點擊按鈕          看到 715          看到 715
立即顯示 715      即時更新          同時更新
   ↓                  ↓               ↓
所有設備同時看到 715（通過 WebSocket 廣播）
```

### 原理

1. **iPhone 點擊** → 發送到後端
2. **後端運算** → 廣播給所有 WebSocket 連接
3. **MacBook & iPad 的 WebSocket** → 接收推送
4. **三台設備同時更新** → 全部顯示 715

## 💡 最佳實踐

### ✅ 應該做

- ✅ 前端立即顯示 +1（無等待）
- ✅ 同時異步發送後端
- ✅ 後端廣播給所有客戶端
- ✅ 前端監聽 WebSocket 更新
- ✅ 多設備同時看到最新計數

### ❌ 不應該做

- ❌ 等後端回應才顯示（用戶感覺慢）
- ❌ 不廣播（只有操作者看到更新）
- ❌ 本地存儲當作真值（會有不一致）
- ❌ 不防重複（數字容易作弊）
