## 四、A6 戰鬥中斷恢復（上線必要條件，已實作；開關 NEXT_PUBLIC_M3_BATTLE_RESUME）

使用者 11/14 21:31 語音核准動架構。實作與原設計稿的差別：快照存的是「伺服端權威核心＋簽章收據」，不是畫面暫存；不必把約 71 個畫面狀態全部序列化。

1. 開局：瀏覽器向 `/api/beast-game/orb-battle-record`（action=start）登記，伺服端核對「回合 0、雙方滿血、敵方數值＝關卡公式、我方攻擊在卡面～強化上限、開局能量不超過鏈上限」後發 battleId 與第 0 號 HMAC 簽章收據。
2. 每一步：寶珠／能量技／連結攻擊／寶器請求都帶收據；伺服端核對「核心雜湊＝上一張收據、序號＝伺服端最新、裝置相同、關卡編號與種子相同、補珠種子＝開局種子＋回合式」，算完發下一號收據與新核心。瀏覽器把它寫入快照（自己 localStorage、親朋好友 sessionStorage；新鍵 match3-battle-resume-*-v1，不動既有鍵）。
3. 重新整理：讀快照 → action=resume。簽章、雜湊、裝置、期限都對才接回；若重整時最後一步剛好送出，直接回伺服端最新核心。同一瀏覽器第二個分頁拿不到 Web Locks 租約，照實提示；跨裝置／舊收據一律被序號擋下。
4. 結算：action=settle，伺服端核心必須敵方全滅、關卡編號一致，同一場只記一次（matchId＝battleId）；保存成功後清掉快照。落敗或中途離開（先確認）＝action=close，之後接回、出手、結算全部拒絕。
5. 損毀、過期（【待平衡暫定值】24 小時）、被竄改：清掉快照、照實提示「這場作廢：不發獎勵、勝場不變，和落敗相同」，再開新的一局。
6. 誠實限制：最新序號存在伺服器行程記憶體。多台伺服器（Vercel 多執行個體）需共用 M3_BATTLE_SECRET 並把紀錄搬進共用資料庫，才有跨執行個體的重放保護；闖關進度本身仍存在瀏覽器（既有設計），清除瀏覽器資料＝放棄這場（與落敗相同）。
