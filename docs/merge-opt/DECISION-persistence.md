# 決策說明：寶珠闖關進度要「單機休閒」還是「伺服器帳號保存」（AUDIT-2 X4）

給：鈺勝　｜　撰寫：fix-3（2026-11-15，UTC+8）　｜　狀態：**等你拍板**，這一輪**沒有改架構**

## 一、現在的狀況（照實）
- 勝場、收據、強化、待餵區、共鳴格全部存在瀏覽器：自己的在 `localStorage` 鍵 `match3-hard-campaign-self-v1`，親朋好友的在 `sessionStorage` 鍵 `match3-hard-campaign-guest-v1`（`lib/beast-game/match3/hard-campaign-store.ts`）。
- A6 伺服端簽章收據只保護「這一場怎麼打」（盤面、血量、序號），保護不到「打完記了什麼」：任何人改 localStorage 就能加勝場、加強化。
- 輸了本來就不扣勝場，所以「逃輸局」實際上沒有得失。
- 換裝置要手動備份／匯入（`campaign-backup.ts`），兩台同時打會各記各的帳（AUDIT-2 M11）。
- 這一輪已做的：伺服端開局只接受合法範圍內的攻擊與能量（M1）；但伺服端不知道你真正有幾勝、強化多少，所以擋不住「範圍內的虛報」。

## 二、兩個選項

### 選項 A：定位成「單機休閒」
進度由瀏覽器保存，接受玩家能改自己的存檔（只影響自己）。

| 面向 | 內容 |
|---|---|
| 好處 | 不用登入、不用資料庫、沒有帳號與個資負擔；離線也能玩；現有程式幾乎不用動 |
| 壞處 | 不能做排行榜、交換、儲值、跨裝置同步；換手機要手動備份；清瀏覽器資料就沒了 |
| 工作量 | 小，約 0.5–1 天：把文件、米其林、畫面上「防竄改」的說法改成「防誤觸、防中斷遺失」；A6 伺服端只保留「接回」用途；補一行「進度存在這台裝置」的提示（信任頁已有類似說明） |
| 風險 | 低。唯一風險是之後要加排行榜或付費時，得再走選項 B |
| 和 A6 的關係 | A6 仍需要共用儲存才能在 Vercel 上開（DESIGN-shared-ledger.md），但它不再承擔「公平性」，可以晚一點做 |

### 選項 B：改成「伺服器帳號保存」
進度存在伺服端，勝場只能由伺服端 settle 寫入。

| 面向 | 內容 |
|---|---|
| 好處 | 真正防竄改；可以做排行榜、交換、儲值；跨裝置自動同步；換手機不會丟 |
| 壞處 | 必須登入（或至少匿名帳號＋綁定）；要資料庫與備份；牽涉個資、隱私權政策、刪除帳號流程；離線不能記帳 |
| 工作量 | 大，估約 2–4 週（推估，未細拆）：帳號與登入、資料表（進度、收據、強化、待餵區）、伺服端改寫 settle／feed／enhance 全部流程、舊瀏覽器存檔一次性搬上伺服器（要防止搬家時灌水）、衝突處理（兩台同時打）、管理後台與客服流程 |
| 風險 | 中到高：搬家時舊存檔無法驗證真偽（只能「信任一次」或從 0 開始）；登入會讓一部分玩家流失；伺服端成本與維運；要和 A6 共用儲存一起設計 |
| 前置 | 先選資料庫（和 A6 同一個），並決定登入方式 |

## 三、我的建議
**先選 A（單機休閒），把 B 列為「要做排行榜或付費時」再啟動的下一階段。**

理由：
1. 目前沒有排行榜、交換、儲值，竄改只影響玩家自己，沒有傷害其他人。
2. B 的工作量和風險都大，而且要先決定登入方式與資料庫；在那之前硬做，反而會拖慢 A6、平衡、五語這些已知扣分項。
3. 選 A 之後要做的事很小，而且能讓「服務誠實度」立刻對齊（文件不再過度宣稱防竄改）。

如果你預計三個月內就要上排行榜或付費，請直接選 B，並先決定資料庫（和 A6 共用）與登入方式。
